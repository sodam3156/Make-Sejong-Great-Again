# RainFlow Sejong

## 문서 목적

RainFlow Sejong은 세종시의 연속 회전교차로 회랑에서 비가 올 때 진입용량이 감소하고 연결도로의 대기행렬이 상류 회전교차로까지 역류해 연쇄 마비로 번지는 위험을 예측하고 복구 대안을 비교하는 운영자 승인형 디지털 트윈이다.

이 문서는 실제 도로를 자동 제어한다고 주장하지 않는다. 해커톤 프로토타입의 목표는 강우와 수요 조건을 재현하고, 무대응과 복구 정책을 동일한 시드로 비교하며, 안전성과 혼잡 전가를 검증한 뒤 운영자가 대응안을 승인하는 전체 흐름을 디지털 콘텐츠로 보여주는 것이다.

연결된 구현 이슈는 [9번 RainFlow Sejong 검증 스파이크](https://github.com/sodam3156/Make-Sejong-Great-Again/issues/9)이다.

## 문제 정의

건조 상태에서는 수요가 회전교차로 용량보다 낮아 정상적으로 처리되더라도, 강우로 운전자의 진입 간격과 차두간격이 증가하면 처리용량이 수요 아래로 떨어질 수 있다. 연속 회전교차로 사이의 짧은 연결도로가 가득 차면 하류 대기행렬이 상류 회전부를 막고, 상류 처리량 저하가 다시 다음 교차로 혼잡을 키우는 연쇄 역류가 발생한다.

RainFlow Sejong이 해결하는 핵심 문제는 단일 회전교차로의 평균 지체가 아니라 회랑 전체의 spillback 발생과 회복이다.

## AX 디지털 콘텐츠 정의

| 계층 | 책임 |
|---|---|
| 강우 디지털 트윈 | 건조, 보통비, 강우 조건에서 진입용량과 회랑 흐름을 합성 큐 모델로 재현한다 |
| 위험 비교 | 동일 시나리오·seed에서 정책별 spillback wall-clock과 링크 상태를 계산한다 |
| 대응안 탐색 | 무대응, 고정 미터링, 연속 게이팅 세 정책을 비교한다 |
| 결정론적 가드 | 안전 위반과 특정 진입로 또는 우회도로로의 과도한 혼잡 전가를 차단한다 |
| 설명 계층 | 검증된 수치로 원인, 대안, 부작용을 운영자에게 설명한다 |
| 인간 승인 | 운영자가 무대응과 후보안을 비교한 뒤 승인, 거절, 보류한다 |
| 결과 재생 | 동일한 초기조건과 시드에서 무대응과 대응 결과를 나란히 보여준다 |

현재 교통 계산 정본은 `rainflow-queue-v2` 결정론적 큐 모델이다. 정책 순위와 설명도 외부 LLM이 아닌 버전이 고정된 규칙 코드가 담당한다.

## 프로토타입 구현 범위

| 항목 | MVP 범위 |
|---|---|
| 도로망 | 연속 회전교차로 3개와 평행 우회로 1개 |
| 시간 구성 | 건조 준비 15분, 우천 첨두 30분, 회복 15분 |
| 날씨 | 건조, 보통비, 강우 단계별 합성 용량계수 |
| 운전자 모델 | 시간단위 유입과 강우별 진입 처리용량 |
| 비교 정책 | `no_action`, `fixed_metering`, `corridor_gating` |
| 반복성 | A·B 각각 seed 1~10과 대표 seed 42 |
| 백엔드 | Python, FastAPI, JSON 실행 저장·JSONL 감사 로그 |
| 시뮬레이션 | 결정론적 큐 모델 `rainflow-queue-v2` |
| 프론트엔드 | 빌드 없는 정적 `frontend/index.html`·CSS·JavaScript·SVG |
| 데이터셋 | `synthetic-v0`만 허용. 실제 자료 어댑터 미설치 |
| 외부 장애 대응 | 요청 시나리오·dataset이 같은 검증 결과만 cached/fixture 폴백 |

현재 제출 범위는 세 회전교차로의 합성 오프라인 의사결정 프로토타입이다. SUMO·실시간 공개데이터·실제 장비 연동은 제출 정본이 아니다.

## 입력과 출력 계약

### 시나리오 입력

| 필드 | 의미 |
|---|---|
| `scenario_id` | `dry_base`, `rain_spillback_a`, `rain_spillback_b` |
| `seed` | 재현용 난수 시드 |
| `data_quality` | 데이터 경과시간·센서 가용성·장비 상태 |
| `dataset_id` | 현재 `synthetic-v0`만 허용 |
| `force_source` | `auto`, `live_simulation`, `cached_simulation`, `fixture` |

### 결과 출력

| 필드 | 의미 |
|---|---|
| `spillback_time_sec` | L12 또는 L23 중 하나 이상이 가득 찬 회랑 wall-clock |
| `recovery_time_sec` | 우천 종료 후 calm이 60초 연속 유지되기 시작한 시각까지의 시간 |
| `recovery_observed` | 회복이 15분 관측창 안에서 확인됐는지 여부 |
| `total_travel_time_sec` | 외부 큐·L12·L23·BYPASS와 우회 자유주행을 포함한 누적 vehicle-seconds |
| `worst_approach_delay_sec` | 실제 service 제약을 반영한 최악 진입로 P95 대기 proxy |
| `dataset` | dataset ID·분류·스키마·어댑터 버전 |
| `reproducibility` | seed·코드·파라미터·KPI·가드·정책·네트워크 버전과 checksum |

프론트엔드의 KPI는 이 결과 JSON만 읽는다. 화면용 수치를 별도로 계산하지 않아 발표 화면과 저장 로그가 달라지는 문제를 막는다.

## 대응 정책

| 정책 | 작동 방식 | 주요 부작용 |
|---|---|---|
| 무대응 | 기존 양보운전과 수요를 유지한다 | spillback 기준선 |
| 고정 미터링 | 우천 중 일부 부진입로 유입을 고정 비율로 제한한다 | 특정 진입로 지체 증가 |
| 연속 게이팅 | 하류 링크 점유에 따라 상류 유입을 연속 조절하고 일부를 BYPASS로 분산한다 | 상류 대기열·우회 전가 가능 |

## 안전과 공정성 가드

| 조건 | 시스템 동작 |
|---|---|
| 하류 링크 저장공간 초과 예측 | 해당 링크 진입 정책을 재탐색한다 |
| 특정 진입로 P95 지체가 기준보다 15퍼센트 초과 악화 | 후보안을 거절한다 |
| 우회도로 지체가 허용한도를 초과 | 우회 비율을 낮추거나 후보안을 거절한다 |
| 진입 차단 이벤트 기반 안전 proxy가 기준보다 증가 | 후보안을 거절한다 |
| 센서 데이터 지연 또는 결측 임계치 초과 | 관찰 전용 모드로 전환한다 |
| 시뮬레이터 실패 | 같은 시나리오·dataset의 검증된 저장 결과가 있을 때만 폴백한다 |
| 운영자 미승인 | 대응 정책을 적용하지 않는다 |

## 기술 스파이크 통과 기준

| KPI | 통과 목표 |
|---|---|
| spillback 누적시간 | 무대응 대비 30퍼센트 이상 감소 |
| 모형 내 누적 체류시간 | 무대응 대비 10퍼센트 이상 감소 |
| 최악 진입로 P95 지체 | 15퍼센트 이상 악화되지 않음 |
| 안전 대리지표 | 기준 대비 악화되지 않음 |
| 재현성 | 같은 입력과 시드에서 같은 결과 생성 |
| 데모성 | 3분 안에 문제 발생, 예측, 후보 비교, 승인, 복구가 보임 |

위 수치는 세종시 실도로 성과가 아니라 프로토타입 기술 스파이크의 통과 기준이다.

## 3분 데모 흐름

| 시간 | 화면과 사건 |
|---|---|
| 0분에서 30초 | 건조 상태에서 세 개 회전교차로가 정상 작동한다 |
| 30초에서 60초 | 강우가 시작되고 하류 회전교차로의 진입용량이 감소한다 |
| 60초에서 80초 | 대기행렬이 연결도로를 채우고 상류 회전부로 역류한다 |
| 80초에서 105초 | 동일 run의 세 정책 KPI와 가드 결과를 제시한다 |
| 105초에서 125초 | 세 가지 대응안을 비교하고 안전 또는 공정성 위반안을 탈락시킨다 |
| 125초에서 160초 | 운영자가 가드를 통과한 연속 게이팅안을 승인한다 |
| 160초에서 180초 | 무대응과 대응의 spillback 시간, 회복 여부, 누적 체류시간, 최악 진입로 P95 대기 proxy를 비교한다 |

## 구현 경계

프로토타입이 주장할 수 있는 것은 세종형 가상 회랑에서 우천과 수요 변화로 발생하는 spillback을 재현하고 여러 대응정책의 효과와 부작용을 비교했다는 점이다.

실제 세종시의 우천 교통개선율, 실제 교통신호 또는 VMS 제어, 실도로 안전성, 도시 전체 확장성은 실측 데이터와 관계기관 검증 전에는 주장하지 않는다.

실제 자료가 필요한 단계와 최소자료, 원문 보존, dataset manifest, 별도 adapter PR, 실패 시 복귀 불변조건은 [RainFlow 데이터 필요조건·투입·롤백 기준](evidence/rainflow_data_requirements.md)을 따른다. 기관 회신 파일을 합성 상수나 fixture에 직접 덮어쓰지 않는다.
