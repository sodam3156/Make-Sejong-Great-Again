# RainFlow Sejong

## 문서 목적

RainFlow Sejong은 세종시 절재로의 연속 교차로 회랑에서 비가 올 때 진입용량이 감소하고 연결도로의 대기행렬이 상류 교차로까지 역류해 연쇄 마비로 번지는 위험을 예측하고 복구 대안을 비교하는 운영자 승인형 디지털 트윈이다.

이 문서는 실제 도로를 자동 제어한다고 주장하지 않는다. 해커톤 프로토타입의 목표는 강우와 수요 조건을 재현하고, 무대응과 복구 정책을 동일한 시드로 비교하며, 안전성과 혼잡 전가를 검증한 뒤 운영자가 대응안을 승인하는 전체 흐름을 디지털 콘텐츠로 보여주는 것이다.

## 대상 구간과 확인 경계

2026-07-29 13:28 KST 실제 세종 도로망 A안 결정에 따라 대상 구간을 실제 교차로로 지정했다. 화면·발표·문서·시뮬레이션 결과의 표시명은 공식 교차로명 원문만 쓰고, `R1`·`R2`·`R3` 같은 임의 별칭은 엔진 내부 키로만 남긴다.

| 순서 | 표시명 | 표준노드 ID |
|---|---|---|
| 1 | 성금교차로 | 4130092501~4130092504 |
| 2 | 청사교차로 | 4130102901~4130102904 |
| 3 | 세종교차로 | 4130138001~4130138004 |

대상 도로 표시명은 **절재로**다. 구간 연결 관계는 국토교통부 표준노드링크 `[2026-07-16]`(세종 지역코드 413, 노드 8,768·링크 11,893)에서 확인했고 실제 경로 길이는 성금~청사 553.7m, 청사~세종 2,669.9m다. 상세는 [`docs/evidence/public_data_inventory_20260729.md`](evidence/public_data_inventory_20260729.md) 1-1절이다.

확인 경계는 다음과 같다. **확인 전 값을 실측값처럼 표시하지 않는다.**

| 항목 | 상태 |
|---|---|
| 교차로 이름·위치, 구간 연결 관계와 경로 길이 | 확인 |
| 교차로 형식(회전 또는 신호) | 미확인. 표준노드링크에 회전교차로 전용 노드유형이 없고, 2023년 공개 신호자료 기준으로는 세 곳 모두 고정시간 신호제어다 |
| 차로수·저장공간·용량 | 모형 가정. 실제 제원 회신 대기 |
| 교통 수요와 KPI | 합성(`synthetic-v0`, `provisional`) |

이 문서와 화면·발표는 세 교차로를 **회전교차로라고 단정하지 않는다.** 아래 1차 근거의 강우 민감도는 회전교차로 진입행태 문헌에서 가져온 초기 가정이며, 대상 구간의 현재 구조가 확인되면 다시 검토한다.

연결된 구현 이슈는 [9번 RainFlow Sejong 검증 스파이크](https://github.com/sodam3156/Make-Sejong-Great-Again/issues/9)이다.

## 문제 정의

건조 상태에서는 수요가 교차로 용량보다 낮아 정상적으로 처리되더라도, 강우로 운전자의 진입 간격과 차두간격이 증가하면 처리용량이 수요 아래로 떨어질 수 있다. 연속 교차로 사이의 짧은 연결도로가 가득 차면 하류 대기행렬이 상류 교차로를 막고, 상류 처리량 저하가 다시 다음 교차로 혼잡을 키우는 연쇄 역류가 발생한다.

RainFlow Sejong이 해결하는 핵심 문제는 단일 교차로의 평균 지체가 아니라 회랑 전체의 spillback 발생과 회복이다.

## AX 디지털 콘텐츠 정의

| 계층 | 책임 |
|---|---|
| 강우 디지털 트윈 | 건조, 약우, 보통비, 강우 조건에서 차량 진입행태와 회랑 흐름을 재현한다 |
| 위험 비교 | 동일 시나리오·seed에서 정책별 spillback wall-clock과 링크 상태를 계산한다 |
| 대응안 탐색 | 유입계량, 연속 게이팅, 속도유도, 제한적 우회 조합을 비교한다 |
| 결정론적 가드 | 안전 위반과 특정 진입로 또는 우회도로로의 과도한 혼잡 전가를 차단한다 |
| 설명 계층 | 검증된 수치로 원인, 대안, 부작용을 운영자에게 설명한다 |
| 인간 승인 | 운영자가 무대응과 후보안을 비교한 뒤 승인, 거절, 보류한다 |
| 결과 재생 | 동일한 초기조건과 시드에서 무대응과 대응 결과를 나란히 보여준다 |

교통 계산은 SUMO와 TraCI 또는 검증 가능한 큐 기반 모델이 담당한다. LLM은 제어값을 임의 생성하지 않고 계산된 결과의 설명과 운영자용 요약만 담당한다.

## 프로토타입 구현 범위

| 항목 | MVP 범위 |
|---|---|
| 도로망 | 절재로 회랑 교차로 3개(성금·청사·세종)와 대체 경로 1개 |
| 시간 구성 | 건조 준비 15분, 우천 첨두 30분, 회복 15분 |
| 날씨 | 건조, 약우, 보통비, 강우 |
| 운전자 모델 | speedFactor 감소, tau와 minGap 증가, 비우선 진입간격 증가 |
| 초기 민감도 | 임계간격 1.08배에서 1.13배, 후속차두 1.06배에서 1.12배, 용량 0.83배에서 0.95배 |
| 비교 정책 | 무대응, 고정 미터링, 연속 게이팅, 게이팅과 속도유도 결합 |
| 반복성 | 동일 시드 재현과 시나리오별 난수 시드 반복 |
| 백엔드 | Python, FastAPI, SQLite |
| 시뮬레이션 | SUMO, TraCI |
| 프론트엔드 | React 또는 Next.js, TypeScript, SVG 회랑 뷰, Recharts 또는 ECharts |
| 외부 장애 대응 | 저장된 결과 JSON과 로컬 설명 폴백으로 핵심 데모 유지 |

2주 프로토타입에서는 교차로를 5개까지 확장하거나 실시간 공개 데이터를 연동하는 작업보다 절재로 세 교차로에서 spillback이 발생하고 복구되는 장면을 재현 가능하게 만드는 것을 우선한다.

## 입력과 출력 계약

### 시나리오 입력

| 필드 | 의미 |
|---|---|
| scenario_id | 시나리오 식별자 |
| seed | 재현용 난수 시드 |
| rain_level | 강우 단계 |
| demand_profile | 진입로별 시간대 수요 |
| incident | 사고 또는 차로 제한 여부 |
| policy | 적용할 복구 정책 |
| network_version | 도로망 버전 |

### 결과 출력

| 필드 | 의미 |
|---|---|
| spillback_seconds | 성금~청사 또는 청사~세종 구간 중 하나 이상이 가득 찬 회랑 wall-clock |
| spillback_events | 상류 교차로 도달 횟수 |
| recovery_seconds | 우천 종료 후 calm이 60초 연속 유지되기 시작한 시각, 미회복 여부 별도 표시 |
| total_travel_time | 외부 큐·회랑 두 구간·대체 경로와 우회 자유주행을 포함한 누적 vehicle-seconds |
| completed_trips | 완료 통행량 |
| approach_p95_delay | 실제 service 제약을 반영한 진입로별 P95 대기 proxy |
| diversion_delay | 우회도로 전가 지체 |
| safety_proxy | 진입 차단 이벤트 기반 안전 proxy |
| guard_result | 안전성과 공정성 가드 통과 여부 |

프론트엔드의 KPI는 이 결과 JSON만 읽는다. 화면용 수치를 별도로 계산하지 않아 발표 화면과 저장 로그가 달라지는 문제를 막는다.

## 대응 정책

| 정책 | 작동 방식 | 주요 부작용 |
|---|---|---|
| 무대응 | 기존 양보운전과 수요를 유지한다 | spillback 기준선 |
| 고정 미터링 | 정해진 시간 동안 우세 방향 유입을 보류한다 | 반대 진입로 지체 증가 |
| 연속 게이팅 | 하류 링크 점유가 임계치에 도달하기 전에 상류 유입을 조절한다 | 상류 대기열 증가 |
| 속도 유도 결합 | 차량 도착군집과 급제동을 완화한다 | 운전자 순응도 가정 필요 |
| 제한적 우회 | 여유가 있는 평행도로로 일부 수요를 분산한다 | 생활도로 혼잡 전가 가능 |

## 안전과 공정성 가드

| 조건 | 시스템 동작 |
|---|---|
| 하류 링크 저장공간 초과 예측 | 해당 링크 진입 정책을 재탐색한다 |
| 특정 진입로 P95 지체가 기준보다 15퍼센트 초과 악화 | 후보안을 거절한다 |
| 우회도로 지체가 허용한도를 초과 | 우회 비율을 낮추거나 후보안을 거절한다 |
| 급제동 또는 TTC 위험이 기준보다 증가 | 후보안을 거절한다 |
| 센서 데이터 지연 또는 결측 임계치 초과 | 관찰 전용 모드로 전환한다 |
| 시뮬레이터 또는 설명 모델 실패 | 무대응 기준안과 저장된 설명으로 복귀한다 |
| 운영자 미승인 | 대응 정책을 적용하지 않는다 |

## 기술 스파이크 통과 기준

| KPI | 통과 목표 |
|---|---|
| spillback 누적시간 | 무대응 대비 30퍼센트 이상 감소 |
| 총 통행시간 | 무대응 대비 10퍼센트 이상 감소 |
| 최악 진입로 P95 지체 | 15퍼센트 이상 악화되지 않음 |
| 안전 대리지표 | 기준 대비 악화되지 않음 |
| 재현성 | 같은 입력과 시드에서 같은 결과 생성 |
| 데모성 | 3분 안에 문제 발생, 예측, 후보 비교, 승인, 복구가 보임 |

위 수치는 세종시 실도로 성과가 아니라 프로토타입 기술 스파이크의 통과 기준이다.

## 3분 데모 흐름

| 시간 | 화면과 사건 |
|---|---|
| 0분에서 30초 | 건조 상태에서 세 개 교차로가 정상 작동한다 |
| 30초에서 60초 | 강우가 시작되고 하류 교차로의 진입용량이 감소한다 |
| 60초에서 80초 | 대기행렬이 연결도로를 채우고 상류 교차로로 역류한다 |
| 80초에서 105초 | 동일 run의 세 정책 KPI와 가드 결과를 제시한다 |
| 105초에서 125초 | 세 가지 대응안을 비교하고 안전 또는 공정성 위반안을 탈락시킨다 |
| 125초에서 160초 | 운영자가 연속 게이팅과 속도유도 결합안을 승인한다 |
| 160초에서 180초 | 무대응과 대응의 spillback 시간, 회복시간, 최악 진입로 지체를 비교한다 |

## 구현 경계

프로토타입이 주장할 수 있는 것은 절재로 회랑을 대상으로 한 합성 시나리오에서 우천과 수요 변화로 발생하는 spillback을 재현하고 여러 대응정책의 효과와 부작용을 비교했다는 점이다.

실제 세종시의 우천 교통개선율, 실제 교통신호 또는 VMS 제어, 실도로 안전성, 도시 전체 확장성은 실측 데이터와 관계기관 검증 전에는 주장하지 않는다.
