# RainFlow Sejong 병렬 제작 운영 및 최영 작업 명세

문서 상태는 2026년 7월 27일 확정본이다. 목표는 2026년 8월 1일 밤까지 Windows x64 외부 컴퓨터에서 즉시 실행되는 RainFlow Sejong 프로토타입을 동결하고 8월 2일에 제출하는 것이다.

모든 팀원은 AI 도구를 사용한다. 아래 역할은 일을 독점한다는 뜻이 아니라 결과에 최종 책임을 지는 담당자를 뜻한다. 공통 계약과 대체 입력을 첫날 고정하여 누구의 지연도 다른 사람의 작업 시작을 막지 않게 한다.

## 최신 역할 결정

| 담당 | 최종 책임 | 독립 작업 방식 | 완료 산출물 |
|---|---|---|---|
| 준 | PM, 제품 범위, 사용자 흐름, 정보구조, 와이어프레임, 화면 문구, 핵심 시연 프론트, 최종 통합과 승인 | 백엔드를 기다리지 않고 fixtures로 앱 골격과 정상에서 복구까지의 상태 흐름을 구현 | 실행 가능한 핵심 프론트, UX 명세, 3분 시연 경로, 최종 승인 기록 |
| 최영 | 기술 리드, AI 설계, 교통 시뮬레이션, 정책 비교, 안전 가드, FastAPI, fixtures, Windows 실행 번들 | 프론트를 기다리지 않고 동결된 입력과 출력 스키마 및 API 계약으로 단독 실행 | 백엔드 전체, OpenAPI, 시뮬레이션 결과, 오프라인 폴백, 로그, start.bat 실행본 |
| 시우 | 세종 문제 근거, 우천 시나리오 수치, KPI 정의, 공정성 기준, 팩트체크와 QA | 구현을 기다리지 않고 provisional 값을 먼저 만들고 결과 수신 후 검증본으로 교체 | 시나리오 기준표, KPI 계산표, 안전 가드 통과 기준, QA 결과 |
| 프론트엔드 담당 | 준이 지정한 컴포넌트, 반응형 정리, 오류 상태, 버그 수정, 외부 PC 실행 검증 | 준의 전체 화면 완성을 기다리지 않고 Storybook 또는 독립 목업으로 컴포넌트 제작 | KPI 카드, 정책 비교 패널, 경고와 승인 모달, 반응형 화면, 실행 점검 결과 |
| 디자인 담당 | 확정된 와이어프레임의 색상, 아이콘, 배경, 상태별 그래픽과 애니메이션 에셋 | 구현을 기다리지 않고 고정된 화면 ID와 에셋 규격으로 제작 | 디자인 토큰, 정상과 우천과 마비와 복구 상태 에셋, 발표 시각물 |

## 첫날 동결할 공통 계약

| 계약 | 동결 내용 | 변경 원칙 |
|---|---|---|
| 화면 상태 | normal, rain_warning, spillback, policy_compare, safety_review, operator_approval, recovery_compare | 7월 28일 밤 이후 기존 상태명 변경 금지, 새 상태는 선택적으로만 추가 |
| 시나리오 | dry_base, rain_spillback_a, rain_spillback_b | 수치 조정은 허용하되 ID 변경 금지 |
| 정책 후보 | no_action, fixed_metering, corridor_gating | 정책 설명은 바꿀 수 있으나 ID와 결과 구조 변경 금지 |
| 핵심 KPI | spillback_time_sec, recovery_time_sec, total_travel_time_sec, worst_approach_delay_sec | 단위 변경 금지, 계산 수정 시 시우 검증 필수 |
| 결과 출처 | live_simulation, cached_simulation, fixture | 화면이 현재 출처를 항상 표시 |
| API | GET /api/health, POST /api/simulations, GET /api/simulations/{run_id}, POST /api/approvals | 파괴적 변경 금지, 필요한 필드는 선택 속성으로 추가 |
| 오류 처리 | 백엔드 실패 시 fixture, LLM 실패 시 규칙 기반 설명, SUMO 실패 시 사전 계산 결과 | 폴백 전환 뒤에도 3분 시연 흐름을 끝까지 완주 |

프론트와 백엔드는 같은 샘플 JSON을 각자 보관한다. 최영이 실제 API를 완성하기 전에도 준과 프론트엔드 담당은 샘플 JSON으로 모든 화면을 구현한다. 준의 화면이 완성되기 전에도 최영은 계약 테스트로 API를 검증한다. 시우의 최종 수치가 늦어지면 provisional 값을 사용하고 검증 완료 후 값만 교체한다. 디자인 에셋이 늦어지면 기본 SVG와 CSS 도형으로 시연을 유지한다.

## 최영 책임 범위

| 작업 영역 | 최영이 해야 할 일 | 완료 기준 | 권장 저장 위치 |
|---|---|---|---|
| 입력과 출력 계약 | 시나리오 입력, 타임라인, KPI, 정책 후보, 안전 검증, 승인 결과 스키마를 확정하고 예제 JSON 제공 | 프론트가 백엔드 없이 예제만으로 전체 흐름 완주 | contracts/rainflow.schema.json, backend/fixtures/demo_run.json |
| FastAPI 골격 | health, 시뮬레이션 실행, 결과 조회, 운영자 승인 엔드포인트 구현 | 자동 API 문서와 계약 테스트 통과 | backend/app/main.py, backend/app/api |
| 교통 모델 | 절재로 회랑 교차로 3개(성금·청사·세종)와 대체 경로 1개에서 건조 상태와 우천 spillback 재현 | 같은 seed에서 결과 재현, 우천 시 상류 역류 발생 | backend/app/simulation |
| 대응 정책 | 무대응, 고정 미터링, 연속 게이팅을 같은 조건에서 비교 | 세 후보의 KPI가 동일 구조로 반환 | backend/app/policies |
| 안전 가드 | 시우가 정의한 최악 진입로 지체와 공정성 기준으로 위험 후보 차단 | 탈락 사유가 코드와 응답에 남고 승인 API가 차단 후보를 거부 | backend/app/safety |
| AI 설계 | 수치와 규칙을 근거로 후보를 순위화하고 설명 생성 | 외부 LLM이 없어도 규칙 기반 설명으로 같은 응답 구조 유지 | backend/app/decision |
| 폴백 데이터 | 실제 계산 결과를 검증한 뒤 제출용 fixture로 동결 | 네트워크, API 키, SUMO 없이 모든 장면 재생 | backend/fixtures |
| 로그와 재현성 | seed, 입력, 후보 점수, 가드 결과, 승인, 결과 출처를 기록 | 시연 한 회차를 JSON 로그로 재생 가능 | backend/logs |
| Windows 패키징 | 프론트 정적 빌드를 백엔드가 제공하도록 묶고 PyInstaller 기반 Windows x64 번들 및 start.bat 제작 | 새 Windows PC에서 런타임 설치 없이 60초 안에 브라우저 표시 | release/windows-x64 |
| 개발 재현 | 선택 경로로 docker compose 실행 지원 | 문서의 한 명령으로 개발 환경 실행 | compose.yaml, docs/RUNBOOK.md |

## 준이 직접 통제할 프론트와 위임 범위

| 구분 | 준이 직접 책임질 범위 | 프론트엔드 담당에게 위임할 범위 |
|---|---|---|
| 앱 구조 | 앱 골격, 라우팅, 전역 상태, 정상에서 복구까지의 핵심 흐름 | 지정된 페이지와 컴포넌트 내부 구현 |
| 데이터 연결 | fixture와 API 전환 어댑터, 실패 시 데모 모드 | KPI 카드와 정책 패널의 데이터 표시 |
| 핵심 상호작용 | 경고, 정책 비교, 안전 검증, 승인, 전후 재생의 순서 | 모달, 버튼 상태, 반응형, 접근성, 오류 화면 |
| 품질 결정 | 시연 경로 통합, 삭제 기준, 최종 승인 | 버그 재현과 수정, 외부 PC 반복 테스트 |

프론트엔드 담당은 UX를 추측해 확장하지 않는다. 명세가 애매하면 준에게 선택지를 제시하고, 답을 기다리는 동안 독립 컴포넌트와 테스트를 진행한다. 지정 화면 하나를 7월 28일 안에 fixture로 완성하지 못하면 핵심 시연 프론트의 구현 권한은 준에게 집중하고 기존 담당은 컴포넌트와 QA 보조로 전환한다.

## 병렬 작업 규칙

| 상황 | 즉시 적용할 규칙 |
|---|---|
| 백엔드가 늦음 | 프론트는 demo_run.json으로 계속 구현하고 API adapter만 나중에 교체 |
| 프론트가 늦음 | 최영은 계약 테스트와 독립 API 클라이언트로 백엔드를 완료 |
| 디자인이 늦음 | 기본 SVG, CSS 도형, 시스템 폰트로 기능 시연 유지 |
| 근거 검증이 늦음 | provisional 표식을 붙인 값으로 구현하고 최종 수치만 교체 |
| LLM이 실패함 | 규칙 기반 순위와 저장된 설명을 반환 |
| SUMO가 실패함 | 같은 스키마를 반환하는 결정론적 큐 모델 또는 검증된 fixture 사용 |
| 통합에서 계약 충돌 | 기존 필드는 유지하고 새 필드만 선택 속성으로 추가 |
| 한 사람이 막힘 | 당일 게이트를 줄이지 않고 대체 입력과 폴백으로 다른 네 명은 계속 진행 |

## 최종 통과 기준

| 검증 항목 | 통과 조건 |
|---|---|
| 외부 실행 | Windows x64에서 Node, Python, SUMO, API 키, 인터넷 없이 start.bat 실행 |
| 시작 속도 | 압축 해제 후 60초 이내 브라우저 화면 표시 |
| 시연 완주 | 정상, 강우 경고, spillback, 세 정책 비교, 안전 가드, 운영자 승인, 복구 비교를 3분 안에 완료 |
| 재실행 | 연속 두 번 실행해도 포트 충돌과 잔류 프로세스 오류 없음 |
| 경로 호환 | 한글과 공백이 포함된 폴더에서 실행 |
| 재현성 | 같은 seed와 입력에서 같은 KPI와 후보 순위 반환 |
| 폴백 | live_simulation 실패 시 cached_simulation 또는 fixture로 자동 전환하고 출처 표시 |
| 설명 책임 | 모든 정책 순위와 탈락에 수치 또는 안전 규칙 근거 표시 |
| 버전 일치 | README, 실행 ZIP, 소스, 데모 영상, 발표 수치가 같은 릴리스 기준 |

이 문서의 우선순위는 완벽한 실시간 AI보다 외부 컴퓨터에서 끊기지 않는 한 장면의 완주다. 유지해야 할 핵심은 우천 마비 재현, 대응안 비교, 안전 가드, 인간 승인, 무대응과 대응의 결과 비교다.
