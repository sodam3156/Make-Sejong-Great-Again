# TATS 지도 중심 UI·UX 방향 V1

> 상태: 2026-08-04 사용자 확정 방향
>
> 적용 대상: Manyfast PRD·와이어프레임, Unity/웹 UI, 디자인 에셋, QA
>
> 우선순위: 이 문서는 `archive/legacy-rainflow-v1/docs/13_DESIGN_FRONTEND_ASSET_SPEC.md`와
> `archive/legacy-rainflow-v1/docs/17_GAME_DESIGN_V1.md`의 정책 카드·자동 건물 성장 UI보다 우선한다.
> 서버 권위, 결정론, 로컬 저장 규칙은 유지하되 RainFlow 계약과 실행물은 레거시 격리본으로만 참조한다.

## 1. 한 줄 방향

**실제 도로를 본뜬 친근한 도시 지도를 계속 보면서 직접 신호를 설계하고,
진단 오버레이로 원인을 찾고, 포인트로 도로와 건물을 성장시킨 뒤,
스킬북에서 고른 알고리즘을 AI에게 그대로 실행시켜 실제 AI 기록과 겨룬다.**

## 2. 매력 포인트와 화면이 증명해야 할 것

Obsidian 정본의 핵심 판타지는 다음과 같다.

| 매력 포인트 | 화면이 증명해야 할 변화 |
|---|---|
| “내가 해도 지금보단 잘하겠다” | 플레이어가 직접 바꾼 신호 단계와 결과의 연결이 보인다. |
| 내 설계로 지역을 살린다 | 정체·이탈이 줄고 목적지 도착 유동량이 늘어나는 장면을 지도에서 확인한다. |
| 성장으로 더 강한 수요를 견딘다 | 도로 개방과 건물 업그레이드가 새 차량·보행자를 만들고 다음 문제를 발생시킨다. |
| AI를 이긴다 | 같은 조건의 Luna·Terra·Sol 기록과 플레이어의 유동량·안전·개방 과정을 비교한다. |
| 실제 도로 기반이지만 어렵지 않다 | A/B Street식 지도 정보 밀도를 유지하되 친근한 건물·차량·보행자 표현을 사용한다. |
| 알고리즘을 배우고 실험한다 | 스킬북에서 알고리즘 원리와 trade-off를 읽고 AI 적용 결과를 직접 수정할 수 있다. |

숫자만 변하고 도시 모습이 변하지 않으면 위 판타지는 성립하지 않는다. 교통,
성장, 위험과 AI 행동의 결과는 항상 지도 표현과 수치 근거를 함께 갱신한다.

## 3. 레퍼런스별 채택 범위

| 레퍼런스 | 채택 | 제외 |
|---|---|---|
| 사용자 제공 TATS 이미지 | 밝고 친근한 탑다운 도시, 차량·보행자·신호가 동시에 보이는 장면, 혼잡의 즉시 판독 | 화면 하단의 긴 신호 블록 끼워 맞추기 |
| Oxygen Not Included | 특정 버튼으로 진단 오버레이 활성화, 비관련 화면 감색, 우측 범례·선택 대상 정보 | 여러 진단창을 겹쳐 띄우는 복잡한 창 관리 |
| A/B Street | 실제 도로 형상, 지도 위 이동 흐름, 교차로 선택과 신호 단계·허용 이동 편집 | 개발 도구처럼 보이는 원시 데이터 중심 UI |
| Obsidian TATS 정본 | 직접 설계, 지역 복구·성장, AI 대결, 실제 도로, 친근한 시각 표현 | 과거 3개 정책 변수와 자동 건물 승급 |

## 4. 기본 화면 구조

기준 프레임은 1440×900, 최소 지원은 1280×720이다. 8px 간격 체계와
최소 44×44 클릭 영역을 유지한다.

```text
┌──────────────────────────────────────────────────────────────────────────┐
│ Day/시각 · 포인트 · 시간 정지/1/3/5배속 · AI 상대 · 서버 연결 상태     │ 64
├──────────────────────────────────────────────────────┬───────────────────┤
│                                                      │ 선택 대상 패널     │
│ 실제 도로 기반 도시 지도                            │ - 교차로/건물/도로 │
│ 차량·보행자·신호·건물 외형                          │ - 현재 값/원인     │
│ 활성 진단 오버레이가 이 지도에 직접 표시됨           │ - 다음 행동        │
│                                                      │ - 범례/단위         │
├──────────────────────────────────────────────────────┴───────────────────┤
│ 선택 기능 한 줄 설명                                                      │
│ [선택] [진단] [신호 편집] [스킬북] [도로 개방] [건물] [AI 비교]          │
└──────────────────────────────────────────────────────────────────────────┘
```

### 4.1 상단 HUD

- `Day N · HH:MM`: `cityClock`임을 문구로 고정한다.
- 포인트: 현재 보유량과 다음 정산까지 남은 도시 시간을 함께 표시한다.
- 시간 제어: 정지, 1배속, 3배속, 5배속을 한 그룹으로 표시한다.
- 신호 편집·스킬북·건물 패널을 열어도 현재 속도를 유지한다.
- 서버 상태: 연결됨, 적용 요청 중, 재연결 중, 재개 준비를 텍스트와 아이콘으로 표시한다.
- AI 상대: 선택한 모델명과 현재 유동량 격차만 간결하게 표시한다.

### 4.2 지도

- 기본 상태는 친근하고 채도가 있는 도시 장면이다.
- 교차로·건물·개방 후보 도로는 클릭 가능한 시각 상태를 가진다.
- 멀리서는 도로 개방 범위·건물 레벨·혼잡 등급을, 가까이서는 차량·보행자·신호 방향을 보인다.
- 선택 대상은 외곽선, 핀과 우측 패널 제목을 함께 바꾼다.
- 진단 오버레이 중에는 비관련 지형을 감색하고 선택 레이어만 강조한다.

### 4.3 우측 선택 대상 패널

패널 폭은 360~400px이다. 지도 선택에 따라 내용을 교체하되 위치는 고정한다.

| 선택 대상 | 필수 정보 | 주요 행동 |
|---|---|---|
| 교차로 | 현재/다음 단계, 전체 주기, 방향별 대기열, 보행 대기, 안전 상태 | 신호 편집, 영향 미리보기 |
| 건물 | 유형, Level, 차량·보행자 생산량, 시간대별 수요, 인접 영향 도로 | 업그레이드 |
| 도로 | 개방 여부, 연결 노드, 현재 유동량, 개방 비용, 개방 후 유입 예상 | 도로 개방권 구매 |
| 진단 구간 | 레이어 값, 단위, 정상 범위, 문제 원인 | 관련 교차로·건물로 이동 |

### 4.4 하단 기능 도크

하단은 신호 타임라인이 아니라 주요 기능의 고정 진입점이다.

| 버튼 | 한 줄 설명 | 결과 |
|---|---|---|
| 선택 | 교차로·건물·도로를 선택합니다 | 기본 지도 선택 모드 |
| 진단 | 혼잡·이탈·위험 원인을 지도에서 찾습니다 | 진단 레이어 버튼 행 표시 |
| 신호 편집 | 선택 교차로의 단계와 시간을 설계합니다 | 우측 신호 편집 패널 |
| 스킬북 | 알고리즘을 배우고 AI에게 그대로 적용합니다 | 책 형태 스킬 트리 |
| 도로 개방 | 연결된 다음 도로의 비용과 효과를 봅니다 | 개방 후보 강조 |
| 건물 | 유동 생산과 업그레이드 가능한 건물을 봅니다 | 업그레이드 가능 건물 강조 |
| AI 비교 | 같은 조건의 AI 기록과 현재 운영을 비교합니다 | 비교 패널 또는 하루 결과 |

활성 버튼은 아이콘, 채움색과 텍스트 상태를 함께 사용한다. 포인터를 올리거나
키보드로 포커스하면 도크 위 설명 영역에 목적·입력·예상 결과를 한 문장으로 표시한다.

## 5. 진단 오버레이

### 5.1 공통 규칙

1. 한 번에 하나의 진단 레이어만 활성화한다.
2. 활성 레이어 버튼을 다시 누르거나 `Esc`를 누르면 기본 지도로 돌아온다.
3. 레이어 전환은 게임의 정지·배속, 지도 카메라와 선택 대상을 바꾸지 않는다.
4. 지도 색만으로 의미를 전달하지 않고 패턴, 방향 화살표, 수치 배지를 함께 사용한다.
5. 우측 범례에는 색 의미, 단위, 집계 구간과 마지막 서버 tick을 표시한다.
6. 레이어가 설명하는 문제에서 바로 관련 교차로·건물 패널로 이동할 수 있어야 한다.

### 5.2 MVP 레이어

| 레이어 | 지도 표현 | 우측 범례·진단 정보 |
|---|---|---|
| 교통량 | 도로 두께·흐름 입자, 차량/보행자 토글 | 시간당 완료 유동량, 유입량, 포화도 |
| 대기열 | 접근 방향별 막대·화살표 | 대기 차량 수/길이, 유입 포기 임계 근접도 |
| 보행자 이탈 | 횡단 대기 구역 점 패턴·이탈 아이콘 | 평균·최대 대기, 이탈 수, 영향 신호 단계 |
| 신호 현시 | 현재 녹색 이동 강조, 다음 단계 점선 | 현재/다음 단계, 남은 시간, 전체 주기 |
| 안전 위험 | 충돌 동선 교차부·위험 등급 패턴 | 중첩 흐름, 아차사고 누적, 사고·차단 가능성 |
| 건물 유입 | 건물→도로 방향 화살표·생산 열지도 | 건물별 차량/보행자 생산량과 시간대 배율 |
| 도로 개방 | 개방/잠금/구매 가능 경계 | 연결 조건, 비용, 예상 신규 건물·수요 |

### 5.3 상태

- 데이터 준비 중: 지도는 유지하고 범례에 skeleton과 서버 tick을 표시한다.
- 데이터 없음: 회색으로 숨기지 말고 ‘해당 시간대 데이터 없음’과 원인을 표시한다.
- 연결 중단: 활성 레이어를 보존하되 모든 값에 `정지된 tick` 배지를 붙이고 입력을 막는다.
- 위험 선택: 오렌지 경고로 시작하고 사고 발생·차단 상태만 빨강으로 표시한다.

## 6. 신호 편집 — 블록 끼워 맞추기 제외

신호 편집 중에도 지도와 선택 교차로를 계속 보여준다. 하단에 긴 시간축을 두지 않는다.

### 6.1 우측 편집 패널

- 현재 계획/로컬 초안 탭
- 단계 순서 목록: `1`, `2`, `3` 번호와 방향 미니맵
- 단계별 지속시간: 초 단위 숫자 입력, ± 버튼, 최소시간 표시
- 허용 이동: 차량 방향·보행 횡단 체크 목록
- 우선순위: 차량·보행자 또는 특정 접근 방향
- 자동 계산 표시: 황색, 전적색, 보행자 정리시간, 전체 주기
- 인접 교차로 영향: 오프셋 변화 여부와 영향을 받는 교차로 수
- 하단 고정 행동: `초안 취소`, `영향 미리보기`

단계 순서 변경은 카드 위/아래 이동 버튼과 키보드 조작을 우선한다. 드래그가 제공되더라도
필수 조작이 아니며 시간 길이를 시각 블록의 너비로 맞추게 하지 않는다.

### 6.2 적용 상태

`미적용 초안 → 서버 확인 → 적용 예약 → 안전 전환 → 활성`

각 상태는 현재 계획과 초안을 동시에 보여주고 적용 예정 `trafficSimTime`과 서버 tick을 표시한다.
안전한 계획에는 불필요한 확인창을 띄우지 않는다. 위험 계획은 충돌 방향, 예상 감점,
사고·도로 차단 가능성을 보여준 뒤 `위험 감수 적용`을 선택할 수 있다.

## 7. 신호 알고리즘 스킬북

### 7.1 역할

스킬북은 정답 프리셋 상점이 아니라 알고리즘의 원리와 trade-off를 배우고 실험하는 공간이다.
AI는 선택된 알고리즘을 **그대로** 신호 계획으로 변환하며 다른 전략으로 임의 최적화하지 않는다.

### 7.2 화면 구조

- 하단 도크의 `스킬북`으로 연다.
- 중앙은 펼친 책 형태의 두 페이지를 사용한다.
- 왼쪽: 알고리즘 계열과 연결된 스킬 트리 노드
- 오른쪽: 선택 알고리즘의 원리, 필요한 입력, 적용 범위, 기대 효과, 부작용, 잠금 조건
- 하단: 적용 대상 `현재 교차로/선택 회랑`, `AI로 초안 만들기`
- 스킬북 뒤로 지도와 시간 HUD를 희미하게 유지해 현재 게임 맥락을 잃지 않게 한다.

### 7.3 상태

| 상태 | 표현 | 행동 |
|---|---|---|
| 잠김 | 실루엣, 선행 노드·부족 조건 표시 | 적용 불가 |
| 해금 가능 | 비용/조건과 예상 역할 표시 | 해금 |
| 해금됨 | 고유 아이콘·색상·숙련 배지 | 적용 대상 선택 |
| AI 생성 중 | 알고리즘·대상·서버 상태 표시 | 취소 가능 |
| 초안 생성 | 변경된 단계·시간·우선순위 요약 | 직접 수정, 미리보기, 폐기 |
| 적용 불가 | 원인: 미개방 도로, 대상 없음, 연결 중단 등 | 해결 경로 안내 |

해금 비용과 구체적인 스킬 수치는 플레이타임 밸런스 확정 전 고정하지 않고 콘텐츠 데이터로 둔다.

## 8. 건물 선택과 업그레이드

### 8.1 패널 정보

- 건물 이름·유형·현재 Level
- 현재 차량 유동인구 생산량/도시 시간
- 현재 보행자 유동인구 생산량/도시 시간
- 시간대별 수요 미니 그래프
- 영향을 받는 인접 도로와 방향
- 다음 Level의 차량·보행자 증가량
- 업그레이드 비용과 현재 포인트
- 현재 외형/다음 외형 미리보기
- `업그레이드` 버튼

### 8.2 구매 규칙

- Level 1→2, Level 2→3을 개별 구매한다.
- 수요 배율은 최신 PRD대로 Level 2 `1.2×`, Level 3 `1.5×`를 사용한다.
- 구매 성공 후 포인트, 생산량, 인접 도로 예상 수요와 지도 외형을 같은 응답에서 갱신한다.
- 포인트 부족, 최대 Level, 미개방 건물, 연결 중단에는 버튼을 비활성화하고 이유를 표시한다.
- 감소나 과거 성과 때문에 이미 획득한 Level을 잃지 않는다.

### 8.3 레벨별 외형

건물 유형마다 세 외형이 실루엣 수준에서 구분되어야 한다.

| Level | 공통 변화 | 예시 |
|---|---|---|
| 1 | 낮고 단순한 기본형 | 1~2층, 작은 간판, 기본 옥상 |
| 2 | 높이·폭 또는 기능 요소 추가 | 증축층, 차양, 큰 창, 옥상 설비 |
| 3 | 멀리서도 보이는 대표 요소 추가 | 고층 실루엣, 대형 간판, 정원·태양광·공공 상징물 |

색만 바꾸는 스킨은 레벨 변화로 인정하지 않는다. 카메라 원거리에서도 Level을 구분할 수 있어야 한다.

## 10. 첫 3분 온보딩 반영

별도 튜토리얼 맵을 만들지 않고 실제 시작 교차로의 Day 1 03:00 정지 상태를 사용한다.

1. `신호 현시` 오버레이를 켜 현재/다음 단계를 읽는다.
2. 교차로를 선택해 한 단계의 시간 또는 우선순위를 바꾼다.
3. 영향 미리보기에서 대기열·보행자·위험 변화를 확인한다.
4. 서버 적용 예약과 안전 전환 뒤 기본 지도로 돌아와 결과를 관찰한다.
5. 세 번째 도시 시간 정산에서 현재값·비교 기준·기본 10포인트·증가 보너스를 읽는다.
6. `도로 개방` 모드에서 첫 연결 도로를 구매한다.

도움말은 건너뛸 수 있고 하단 도크에서 다시 열 수 있다. 정답 계획은 제공하지 않는다.

## 12. 수락 기준

### 지도·도크

- [ ] 1440×900과 1280×720에서 지도, 우측 패널, 하단 도크가 스크롤 없이 보인다.
- [ ] 하단에 신호 길이 블록을 조립하는 영역이 없다.
- [ ] 모든 주요 기능 버튼에 아이콘, 이름과 한 줄 설명이 있다.

### 오버레이

- [ ] 7개 MVP 레이어를 버튼으로 전환할 수 있고 한 번에 하나만 활성화된다.
- [ ] 활성 레이어, 범례, 선택 대상 패널과 지도 강조가 같은 데이터를 표시한다.
- [ ] 닫은 뒤 카메라, 선택 대상, 정지·배속 상태가 유지된다.
- [ ] 색각 없이도 패턴·아이콘·수치로 위험 등급을 구분할 수 있다.

### 신호 편집

- [ ] 단계 순서·지속시간·차량·보행자 우선순위를 우측 패널에서 수정할 수 있다.
- [ ] 현재 서버 계획과 로컬 초안을 동시에 구분해 볼 수 있다.
- [ ] 직접 편집과 AI 초안 모두 영향 미리보기와 서버 안전 전환을 거친다.

### 스킬북

- [ ] 잠금·해금 가능·해금됨 상태와 선행 관계가 보인다.
- [ ] 알고리즘의 적용 범위, 기대 효과와 trade-off를 적용 전에 읽을 수 있다.
- [ ] AI가 선택 알고리즘과 다른 전략을 임의로 섞지 않았음을 초안 요약으로 확인할 수 있다.
- [ ] 생성된 초안을 직접 수정·폐기·미리보기 할 수 있다.

### 건물

- [ ] 건물 선택 시 차량·보행자 생산량과 인접 영향 도로가 보인다.
- [ ] 다음 Level의 증가량, 비용과 외형을 구매 전에 비교할 수 있다.
- [ ] Level 1·2·3은 색상만이 아니라 실루엣으로 구분된다.
- [ ] 구매 직후 서버 값과 지도 외형이 일치한다.
