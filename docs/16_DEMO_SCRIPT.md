정본 메타데이터: freeze `freeze-20260729-202509-kst`, source run `live-rain_spillback_a-s42-f3727bcd00`, checksum `c9088907640696c315685619ce18ae1529ceb8bc1e993bb36c0f080b7ce4ed89`, seed `42`, `provisional=true`. 화면의 지명·링크 관계는 2026-07-16 전국표준노드링크 세종 8,768노드·11,893링크를 참조하며, 교통량·저장공간·정책 효과는 합성 결과라 세종 실측 성과가 아니다.

## 0. 시작 전 체크리스트

1. `release\start.bat`을 더블클릭한다. 콘솔에 포트가 뜨고 `/api/health` 응답을 최대 30초 기다린 뒤 기본 브라우저가 `http://127.0.0.1:<PORT>`로 자동으로 열린다 (`release/README_RUN.md`).
2. 화면 우측 상단 배지를 확인한다.
   - `result_source: live_simulation` (파란 배지)면 백엔드가 방금 계산한 결과다. **live 대사**를 쓴다.
   - `result_source: fixture` (노란 배지)면 저장된 결과를 재생 중이다. **fixture 대사**를 쓴다.
   - 두 경우 모두 옆의 `provisional 합성 데이터` 배지가 항상 떠 있다. 이 배지는 반드시 언급한다.
   - 어느 쪽이 뜨든 화면에 보이는 수치와 이 스크립트에 적힌 인용 수치는 같다 (둘 다 `demo_run.json` 값). 대사를 바꿀 필요는 없고 "live" / "저장된" 두 단어만 바꾼다.
3. 시나리오 드롭다운은 `rain_spillback_a`로 둔 채 건드리지 않는다. fixture 모드에서는 다른 값을 고르면 자동으로 `rain_spillback_a`로 되돌아가며 안내 문구가 뜬다. 이 동작은 정상이며 발표 중 시나리오를 바꾸지 않는다.
4. 화면은 기본값으로 자동재생 상태다(`재생` 버튼이 아니라 `일시정지` 버튼이 보이면 이미 재생 중). 7개 의미 상태를 담은 20개 타임라인 표본이 총 180초에 걸쳐 9초 간격으로 자동 전환된다. 발표자는 자동재생을 멈출 필요 없이 말로 흐름을 맞추되, `operator_approval` 상태가 유지되는 약 99~135초 사이에는 반드시 `승인` 버튼을 직접 클릭한다(자동으로 눌리지 않음). 최종 완주는 상태 표시가 `20/20`이 될 때 확인한다.
5. 예행 연습 때 각 구간 대사를 소리 내어 읽어 아래 타임라인의 배정 시간 안에 끝나는지 스톱워치로 확인한다(방법은 6장 참고).

## 2. 핵심 메시지 3줄

발표 어디서든 시간이 남으면 이 세 문장으로 마무리한다.

1. AI는 수치를 만들지 않습니다. 검증된 큐 모델 계산 결과를 설명만 합니다.
2. 가드를 위반한 안은 시스템이 아니라 규칙이 자동으로 탈락시킵니다.
3. 운영자가 승인하기 전까지는 어떤 정책도 적용되지 않습니다.

## 3. 돌발 상황 분기

### live 실패 시

`bootstrap()`이 백엔드 호출을 5초 안에 못 받으면 자동으로 fixture로 폴백해 노란 `result_source: fixture` 배지를 띄운다. 이때 대사:

"백엔드 연결이 지연되어 저장된 검증 결과로 재생 중입니다. 화면에 보이는 수치는 동일한 계산 로직으로 나온 결과입니다."

시나리오 드롭다운을 바꿨는데 실패하면 "시나리오 요청 실패. 이전 데이터를 유지합니다" 안내가 뜬다. 이 경우 드롭다운을 건드리지 않았다고 말하고 진행 중이던 화면으로 계속한다.

### Q&A 대비 5개

1. **"이 수치, 세종시 실측 성과인가요?"**
   아닙니다. `demo_run.json`에 `provisional: true`로 명시된 합성 데이터입니다. 교차로 표시명과 링크 관계만 세종 표준노드링크에서 왔고, 시우 검증 전까지는 프로토타입 기술 스파이크 통과 기준이지 실측 성과가 아닙니다 (`docs/09` 구현 경계).

2. **"왜 SUMO를 안 쓰고 큐 모델을 썼나요?"**
   Day 1~2는 결정론적 큐 모델을 정식 경로로 쓰기로 확정했습니다. SUMO·TraCI는 큐 모델이 3분 데모를 먼저 완주한 뒤의 선택적 업그레이드로 미뤘습니다 (`docs/15_DAY1_FREEZE_DECISION.md` 4항).

3. **"이 시스템이 실제 신호나 VMS를 직접 제어하나요?"**
   아닙니다. 실제 도로를 자동 제어한다고 주장하지 않습니다. 계산은 큐 모델이 하고, AI는 계산된 결과의 설명과 운영자용 요약만 담당합니다 (`docs/09` AX 디지털 콘텐츠 정의).

4. **"같은 조건으로 다시 돌리면 같은 결과가 나오나요?"**
   예. seed 42로 고정되어 있고, 재현성은 `docs/09`의 기술 스파이크 통과 기준 중 하나입니다. 시나리오·시드·정책이 같으면 같은 결과가 나옵니다.

5. **"고정 미터링은 왜 떨어졌나요? 개선율이 더 좋아 보이는데요."**
   spillback만 보면 고정 미터링도 62.4% 줄지만, 성금교차로 서측·청사교차로 남측 진입로의 P95 대기 proxy가 각각 55.4%·938.5% 악화돼 내부 공정성 한도 15%를 넘습니다. 특정 진입로에 피해를 전가하는 안이라 시스템이 자동으로 탈락시킵니다.

## 4. 금지 발언

발표 중 다음은 절대 말하지 않는다.

- 세종시에서 실측으로 개선됐다는 주장 (실측 데이터 없음, 전부 provisional 합성 데이터).
- 실도로 신호·VMS를 이 시스템이 직접 제어한다는 주장 (계산과 설명만 하며, 제어는 사람 승인 뒤에도 이 프로토타입 범위 밖).
- "목표 개선율 OO%"처럼 코드나 대사에 하드코딩된 목표치를 실적인 것처럼 말하는 것. 모든 개선율은 `demo_run.json`의 계산 결과이지 사전에 정한 목표가 아니다.

## 5. 대사 분량 검증 방법

1. 각 구간 대사를 실제로 소리 내어 읽고 스톱워치로 시간을 잰다.
2. 한국어 발화 속도 초당 4~5음절 기준으로, 구간 배정 시간(예: 20초 구간이면 80~100음절)의 80% 이내로 대사를 줄인다. 남는 20%는 클릭·화면 전환 대기·시선 이동 여유분이다.
3. 가장 긴 구간(2:05–2:40, 35초, 승인 버튼 클릭 포함)부터 먼저 읽어보고, 버튼 클릭 동작 시간까지 포함해서 35초 안에 들어오는지 확인한다.
4. 자동재생은 20개 표본을 9초(180초/20) 간격으로 넘기며, 같은 의미 상태가 여러 표본 동안 유지된다. 의미 상태의 실제 노출 구간은 정상 0~45초, 강우 경고 45~63초, spillback 63~81초, 정책 비교 81~90초, 안전 검토 90~99초, 운영자 승인 99~135초, 회복 비교 135~171초다. `docs/09`의 발표 구간 배정과 초 단위로 정확히 일치하지 않으므로 화면 상태를 기준으로 대사를 이어간다.
