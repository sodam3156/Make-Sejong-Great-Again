# 발표 서사

## 1. 한 줄 소개

> 세종은 스마트교차로가 없는 도시가 아니라, 이미 깔린 교차로들을 함께 판단하고 안전하게 운영할 소프트웨어가 부족한 도시입니다.

## 2. 3분 피치

### 문제

세종 행복도시는 스마트시티로 많은 투자를 받았습니다. 광통신망, 온라인 신호제어기, 센서, CCTV, 스마트교차로도 있습니다.

그런데 2025년에는 행복도시 346개 교차로의 실시간 원격제어가 수년째 어렵다는 문제가 공개적으로 제기됐습니다. 돌발 정체가 생기면 경찰관이 현장에 나가 신호를 수동 조작하는 사례도 보도됐습니다.

기술이 없어서가 아닙니다. **시설과 AI 연구 사이에 실제 도시를 운영할 소프트웨어가 빠져 있기 때문입니다.**

### 해결

저희는 기존 ITS 위에 얹는 AI 교통제어 오케스트레이터를 만들었습니다.

교통 흐름, 보행 안전, 긴급 대응, 장비 상태를 보는 AI들이 신호 후보안을 검토합니다. 하지만 AI가 곧바로 신호를 바꾸지는 않습니다.

보행 최소시간과 충돌 신호를 코드로 검사하고, 운영자가 예상효과와 위험을 보고 승인해야만 디지털 트윈에 적용됩니다.

### 데모

사고로 한 교차로의 정체가 인접 교차로까지 번집니다.

AI는 지체를 18% 줄이는 공격적인 안을 제시하지만, 보행 안전시간을 위반해 자동 탈락합니다. 대신 안전 제약을 지키면서 지체를 13% 줄이는 안이 추천됩니다.

운영자가 승인하면 적용 전후 대기행렬과 지체시간이 비교되고, 모든 판단 근거가 로그로 남습니다.

### 결론

우리는 새로운 센서를 더 설치하자고 말하지 않습니다.

> 세종이 이미 가진 눈과 귀를 연결해, 안전하게 판단하고, 사람이 승인하고, 효과를 증명하는 두뇌를 만들겠습니다.

## 3. 심사위원 예상 질문

### “실제 신호기를 제어합니까?”

해커톤에서는 제어하지 않는다. 디지털 트윈에서 추천·안전검증·승인·효과검증을 시연한다. 실제 도입은 읽기 전용 데이터, 섀도 모드, 승인형 제한 실증 순으로 확장한다.

### “기존 스마트교차로와 무엇이 다릅니까?”

단일 기능이나 센서 구축이 아니라 이기종 데이터 통합, 다교차로 파급 분석, 안전 가드, 운영자 승인, 적용 후 검증을 하나의 운영 흐름으로 묶는다.

### “LLM이 교통신호를 정하면 위험하지 않습니까?”

LLM은 후보안 설명과 다중 관점 검토를 담당한다. 수치 계산은 최적화 코드가, 안전 보장은 결정론적 규칙이 담당한다. 승인 없이는 적용되지 않는다.

### “세종시 데이터를 구할 수 있습니까?”

MVP는 재현 가능한 시뮬레이션으로 구현한다. 이후 공개 데이터와 기관 협력 데이터로 보정하고, 처음에는 읽기 전용 섀도 모드로 검증한다.

### “왜 세종이어야 합니까?”

계획도시라 축 단위 실증이 유리하고, 이미 ITS·스마트교차로·C-ITS 기반이 있으며, 동시에 운영 소프트웨어 공백이 공개적으로 확인돼 문제와 해결의 연결이 선명하다.

### “AI 없이도 가능한 것 아닙니까?”

안전 규칙과 신호 계산 일부는 전통 알고리즘이 더 적합하다. AI는 여러 교차로·이해관계·장비 상태를 종합하고 후보안의 이유와 위험을 운영자에게 설명하는 데 사용한다. 이 하이브리드 구조가 핵심이다.
