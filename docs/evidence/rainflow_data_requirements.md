# RainFlow 데이터 필요조건·투입·롤백 기준

**기준일:** 2026-07-29 KST

**현재 기본 데이터셋:** `synthetic-v0`

**현재 상태:** 실제 자료 어댑터 미설치. 합성 기본값만 실행 허용

## 1. 목적별 데이터 필요성

같은 큐 계산식을 사용하더라도 도로별 길이·차로·수요·회전비·처리용량이 다르다. 실제 자료는 계산 항목을 새로 정하기보다 대상 도로의 입력값을 보정하고 결과가 관측과 맞는지 검증하는 데 사용한다.

| 단계 | 목표 | 필요한 데이터 | 장비 기종 필요성 |
|---|---|---|---|
| 합성 해커톤 데모 | 정책 비교·가드·승인 흐름 재현 | 코드에 동결된 합성 수요·용량·저장공간 | 불필요 |
| 실제 회랑 보정 | 특정 도로의 혼잡과 spillback 재현 | 노드·링크·차로·길이, 방향별 교통량, 회전비, 같은 시각 강우 | 센서 제조사보다 위치·측정항목·집계주기·결측률이 중요 |
| 현장 검증 | 계산 결과와 관측값 비교 | 속도·점유율·대기행렬, 사고·공사·행사, 품질 flag | 측정오차·우천 영향 확인 필요 |
| 실제 장비 연동 | 승인 정책을 현장 시스템과 교환 | 제어방식, 신호계획, 통신규격, fail-safe, 연동시험 결과 | 이 단계에서만 제어기 제조사·모델·펌웨어가 중요 |

현재 정본은 신호 없는 합성 연속 회전교차로 3개다. 따라서 신호주기·녹색시간·신호제어기 모델명은 현재 큐 모델의 필수 입력이 아니다. 신호교차로를 범위에 넣을 때만 주기·현시·녹색배분·옵셋·TOD 또는 감응제어 조건을 입력 계약에 추가한다.

## 2. 실제 회랑 보정 최소자료

우선순위 순으로 다음 자료를 확보한다.

1. 후보 회랑의 노드·링크·교차로 형상과 좌표계
2. 링크 길이·차로 수·저장 가능 차량 수의 산정 근거
3. 날짜·시간대·방향별 교통량과 회전 비율
4. 같은 날짜·시간의 강우량 또는 강우강도
5. 가능하면 속도·점유율·대기행렬과 품질 flag
6. 사고·공사·행사·통제 기록
7. 신호교차로가 포함된 경우에만 신호계획과 제어방식

교통량과 강우의 시간축이 맞지 않으면 우천 영향 보정에 사용하지 않는다. 월별 교통량과 특정 시간 강우를 억지로 결합하지 않는다.

## 3. 현재 API 경계

`POST /api/simulations`의 선택 필드 `dataset_id`는 현재 다음 값만 허용한다.

```json
{
  "scenario_id": "rain_spillback_a",
  "seed": 42,
  "dataset_id": "synthetic-v0"
}
```

`sejong-real-v1` 같은 미설치 값은 422로 거절한다. `live_simulation`은 실행 시점에 합성 계산을 수행했다는 뜻이며 실제 교통자료를 사용했다는 뜻이 아니다.

`force_source=live_simulation|cached_simulation|fixture`는 계산 결과의 출처를 고르는 옵션이다. 데이터셋 전환이나 실데이터 롤백 기능으로 해석하지 않는다.

## 4. 실제 자료 수령 후 투입 절차

정보공개청구나 공개 API로 파일을 받아도 기존 상수와 fixture를 바로 덮어쓰지 않는다.

1. 원문을 `data/public/information_requests/<request_id>/raw/`에 그대로 보존한다.
2. 원문 파일별 SHA-256, 기관, 수령일, 기준일, 라이선스·공개범위를 기록한다.
3. 변환본을 별도 `normalized/`에 만들고 원문은 수정하지 않는다.
4. 좌표계·단위·시간대·집계주기·결측률·중복·범위를 검사한다.
5. 다음 필드를 가진 dataset manifest를 작성한다.

```text
dataset_id
data_class = observed | calibrated | synthetic
schema_version
adapter_version
source_request_ids
source_sha256
as_of_date
timezone
spatial_scope
temporal_scope
units
missing_rate
license
approved_by
approved_at
```

6. 전용 어댑터와 테스트를 별도 브랜치·PR에서 구현한다.
7. 실제 자료용 시나리오는 기존 `dry_base`, A, B의 의미를 몰래 바꾸지 않는다. 필요한 경우 새 선택 필드나 별도 dataset manifest로 구분한다.
8. 같은 commit에서 결과 JSON·fixture·화면 라벨·README·데모 대본을 동기화한다.
9. 사람 검토 전에는 실제 자료를 기본값으로 바꾸지 않는다.

## 5. 롤백 불변조건

- 기본값은 계속 `synthetic-v0`다.
- 실제 자료는 명시적인 `dataset_id`를 선택할 때만 사용한다.
- 미확인 또는 스키마 불일치 자료는 자동으로 synthetic 결과로 위장해 성공 처리하지 않는다. 요청을 실패시키고 사유를 기록한다.
- 실데이터 계산 실패와 계산 결과 폴백을 구분한다. 실패한 실제 자료 요청을 오래된 synthetic fixture로 바꿔 `live_simulation`이라고 표시하지 않는다.
- 저장 결과의 `scenario_id`가 요청과 다르면 폴백을 거절한다. A fixture를 B 결과인 것처럼 run ID만 바꿔 반환하지 않는다.
- 기존 `backend/fixtures/demo_run.json`, `cached_run.json`, `BASE_DEMAND`, `LINKS`, `SCENARIOS`를 수령자료로 직접 덮어쓰지 않는다.
- 각 run은 `dataset_id`, `schema_version`, `adapter_version`, `result_source`, `provisional`과 재현 버전을 기록한다.
- 새 자료 PR을 되돌려도 `synthetic-v0`와 동결 API 4경로가 그대로 실행되어야 한다.

## 6. 현재 자료요청과 사용단계

| 요청 ID | 받을 자료의 주용도 | 현재 데모 필수 여부 |
|---|---|---|
| `IR-TRAFFIC-2025`, `IR-TRAFFIC-2026` | 방향·시간대 수요 보정과 건조/우천 비교 | 선택. 합성 데모에는 불필요 |
| `IR-CORRIDOR-LATEST` | 실제 링크·차로·길이·연결관계 확정 | 실제 회랑 주장 시 필수 |
| `IR-SIGNAL-CHANGE-2026` | 신호교차로가 포함될 경우 운영이력·교란요인 확인 | 현재 회전교차로 MVP에는 불필요 |
| `IR-SIGNAL-OPS-2026` | 향후 현장 신호연동 가능성·운영모드 확인 | 현장연동 단계에서 필요 |

제어기 IP·계정·인증키·상세 망 구성·취약점은 수집하지 않는다.

## 7. 승인 판정

| 판정 | 조건 |
|---|---|
| 합성 데모 승인 | `dataset_id=synthetic-v0`, KPI·가드 테스트 통과, 합성·provisional 인접 표기 |
| 실제 회랑 조건부 승인 | manifest·스키마·단위·시간·공간 검증 통과, 보정 절차와 한계 공개 |
| 현장 성과 승인 | 독립된 관측자료로 검증하고 관계기관·운영자 승인 확보 |
| 사용 보류 | 원문 지문, 기준일, 단위, 공간범위 또는 동일 시간대 강우·교통 쌍 중 하나라도 불명확 |

이 문서는 자료가 “있으면 좋다”는 목록이 아니라, 어떤 단계에서 어떤 자료가 있어야 어떤 주장을 할 수 있는지를 제한하는 투입 게이트다.
