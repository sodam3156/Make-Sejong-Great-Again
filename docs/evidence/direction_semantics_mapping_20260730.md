## 1. 확인된 두 가지 정의

### 공개 교통량 자료

공공데이터포털은 세종 교통량 자료를 다음처럼 설명한다.

- `동, 서, 남, 북 교차로 통행방향별` 월별 교통량
- `동`: 동쪽 교통량
- `서`: 서쪽 교통량
- `남`: 남쪽 교통량
- `북`: 북쪽 교통량

공식 페이지:

- https://www.data.go.kr/data/15113448/fileData.do

이 설명은 열이 교차로의 접근로 위치보다 **차량 통행방향**을 나타낸다는 해석을 지지한다. 다만 항목 설명에 `진행방향`이라는 단어가 직접 정의된 것은 아니므로 최종 판정은 제공기관 확인이 가장 안전하다.

### RainFlow 모델

`backend/app/main.py`의 화면 라벨은 suffix를 접근로 위치로 사용한다.

| ID | 화면 라벨 |
|---|---|
| `R1_N` | 성금교차로 북측 진입로 |
| `R1_W` | 성금교차로 서측 진입로 |
| `R2_N` | 청사교차로 북측 진입로 |
| `R2_S` | 청사교차로 남측 진입로 |
| `R3_N` | 세종교차로 북측 진입로 |
| `R3_E` | 세종교차로 동측 진입로 |

따라서 공개자료의 차량 진행방향과 모델의 접근로 위치는 반대 방위로 연결해야 한다.

## 2. 방위 반전 규칙

| 모델 진입로 위치 | 교차로로 들어오는 차량의 진행방향 | 공개자료 열 |
|---|---|---|
| 북측 | 남향 | `남` |
| 서측 | 동향 | `동` |
| 남측 | 북향 | `북` |
| 동측 | 서향 | `서` |

이 규칙은 직선 진행방향의 기하학적 대응이다. 공개자료가 좌회전·직진·우회전을 합친 통과방향인지, 특정 검지기 방위인지에 따라 실제 의미가 달라질 수 있다.

## 3. 외부 수요 접근로 후보

현재 `BASE_DEMAND`가 직접 생성하는 외부 도착수요는 네 접근로다.

| 모델 ID | 화면 접근로 | 후보 공개열 | 정규화 월중앙 방향비중 | 판정 |
|---|---|---|---:|---|
| `R1_N` | 성금 북측 | 성금 `남` | 0.312042 | CANDIDATE |
| `R1_W` | 성금 서측 | 성금 `동` | 0.206793 | CANDIDATE |
| `R2_S` | 청사 남측 | 청사 `북` | 0.346572 | CANDIDATE |
| `R3_E` | 세종 동측 | 세종 `서` | 0.173056 | CANDIDATE |

위 값은 각 교차로 내부의 방향 비중이다. 네 모델 접근로의 절대수요 비율로 바로 정규화할 수 없다.

이유:

1. 서로 다른 교차로에서 집계된 총량이다.
2. 청사와 세종의 방향별 교통량에는 상류 교차로에서 넘어온 통과교통이 포함될 수 있다.
3. 모델의 `R2_S`, `R3_E`는 신규 외부 도착만 생성하지만 공개자료는 신규 유입과 회랑 통과를 분리하지 않는다.
4. 월간 자료이므로 5초·5분·15분 도착률을 직접 제공하지 않는다.

## 4. R2_N·R3_N은 공개 월간 수요와 매핑하지 않음

`simulation.py` 계산을 보면:

- `R2_N` 서비스량은 외부 queue가 아니라 `links["L12"]`에서 나온다.
- `R3_N` 서비스량은 외부 queue가 아니라 `links["L23"]`에서 나온다.

즉 두 ID는 화면상 진입로 라벨을 갖지만 계산상으로는 상류 회랑 흐름의 선두 서비스 라벨이다. `BASE_DEMAND`에도 포함되지 않는다.

따라서:

- `R2_N`에 청사 `남` 또는 다른 공개열을 연결하지 않는다.
- `R3_N`에 세종 `남` 또는 다른 공개열을 연결하지 않는다.
- 이 둘을 외부 수요로 추가하면 상류 통과교통을 중복 집계할 위험이 있다.

## 5. 세종교차로 서 방향 이상치 영향

`R3_E` 후보는 공개자료의 세종 `서` 열과 연결된다. 그러나 2022-08 서 방향 값은 `856`으로 11개월 중앙값 `199,927`의 0.43%에 불과해 `LIKELY_DATA_ERROR`로 판정됐다.

후보표에는 단일 2022-08 비중이 아니라 **월별 방향비중 중앙값을 정규화한 0.173056**을 사용했다. 이는 이상치 영향을 줄이지만 원자료 오류를 해결한 것은 아니다.

## 6. 지금 허용되는 활용

- 공개방향과 모델 접근로의 관계를 리뷰하는 자료
- 두 방향해석 가설 중 하나를 팀이 승인하기 위한 비교표
- 향후 데이터 adapter 입력 필드 설계
- 강건 방향비중 민감도 범위 설계

## 7. 지금 금지되는 활용

- `BASE_DEMAND`를 후보비중으로 즉시 교체
- 네 비중을 합계 1로 다시 정규화해 절대 접근수요로 사용
- 월간 교통량을 5초 도착률로 단순 나눗셈
- `R2_N`, `R3_N`을 외부 방향 교통량으로 추가
- 방향 의미 확인 없이 현장 보정 완료 선언

## 8. 최종 확인 경로

최종 확정은 다음 중 하나가 필요하다.

1. 세종시 또는 공공데이터 제공부서가 `동·서·남·북`을 차량 진행방향이라고 회신
2. 원시 검지기·스마트교차로 데이터의 방향 코드 정의서 확보
3. 대상 교차로의 접근로·검지기 배치도와 공개 방향 합계를 교차검증

이전까지 파일 상태는 `CANDIDATE_REVIEW_REQUIRED`로 유지한다.
