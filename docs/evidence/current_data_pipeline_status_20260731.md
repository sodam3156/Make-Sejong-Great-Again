# RainFlow 데이터 파이프라인 현황 — 2026-07-31

## 현재 상황

현재 데모는 **KMA 세종 관측 강우가 결합된 관측 제약 합성 시나리오**입니다. 세종의 동일 날짜 시간대별 회전교통량, 최신 신호계획, 공식 차로군·대기공간 자료가 없으므로 현장 재현 또는 실제 신호운영 효과라고 표현할 수 없습니다.

이번 단계에서는 기다리는 동안 사용할 수 있는 자료를 실제 전처리했습니다.

- 천안 72개 교차로·243개 접근로·30일 자료에서 교차로별 평일/주말 24시간 프로파일 3,456행 생성
- 천안 유사 교차로 후보 72개를 차로구조가 아니라 `접근로 수+방향 편중+첨두 집중+교통량`으로 1차 선별
- KICT 좌표 3,983행 중 세종 관측지점 기준 80km 이내 1,047개를 확인하고, 가까운 100개와 상시 30개 프로파일 생성
- 제주 100개 교차로의 회전별·차종별 자료를 adapter fixture로 정규화
- 인천 신호주기 3,913행을 숫자형 주기와 TOD fixture로 정규화

모든 외부자료에는 `source_class`, `source_region`, `usable_for_calibration=false`가 붙으며 `BASE_DEMAND`, 용량, 저장공간, 공정성·안전·제어 임계값은 변경하지 않았습니다.

## 추가 자료 도착 시 변경 방식

새 자료는 기존 파생자료를 임의 수정하지 않고 다음 순서로 반영합니다.

1. 원본 파일명·크기·SHA-256과 수령일을 manifest에 추가
2. 자료별 adapter로 canonical CSV/JSON 생성
3. 결측·중복·시간·방향·단위·좌표계 QA 수행
4. `observed`, `regional_reference`, `external_fixture`, `synthetic`를 분리해 결합
5. 백엔드 인계 contract를 갱신하되 런타임 활성화는 별도 승인 PR로 제한
