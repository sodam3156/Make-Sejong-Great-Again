# 모델 형식과 실제 회랑 정렬 결정

- 기준일: 2026-07-31 KST
- 담당 범위: 시우 데이터·근거·KPI·QA
- 실행 코드 파라미터 승인: 포함하지 않음

## 1. 왜 회전교차로 모델이 존재하는가

초기 솔루션 감사에서 제출 변형 `RainFlow Sejong`은 기존 5개 신호교차로 MVP와 분리된 **합성 3개 회전교차로 회랑**으로 의도적으로 선택됐다. 따라서 회전교차로라는 모델 범위 자체가 사용자가 뒤늦게 임의로 추가한 설정은 아니다.

이후 A안에서 성금교차로–청사교차로–세종교차로의 실제 표준 NODE/LINK와 표시명이 도입됐지만, 시뮬레이터 내부의 신호 미모델링 큐·용량 구조는 그대로 남았다. 현재 위험은 다음 두 요소의 결합이다.

1. 원래 모델: `synthetic_three_roundabout_corridor`
2. 현재 표시: 실제 성금·청사·세종교차로 공간망

실제 지명과 합성 회전교차로 역학을 하나의 현장 재현처럼 표현하면 모델 오표현이 된다.

공식 전국 배포 ZIP의 SHA-256은 다음과 같다.

세종 권역 접두어 `413`으로 추출한 결과:

- 성금교차로 4개 NODE

- 세종교차로 4개 NODE

- 청사→세종 절재로 2,669.852m
- 역방향 경로도 별도 확인

표준 NODE/LINK로 직접 사용할 수 있는 항목:

- 교차로 표시명과 좌표
- 도로 링크 연결관계
- 방향 링크별 차로 수
- 제한속도
- 도로명
- 공식 링크 길이
- 회전 연결·제한관계 검토

표준 NODE/LINK만으로 확인할 수 없는 항목:

- 회전교차로 여부
- 신호등 설치·가동 여부
- 주기·현시·옵셋
- 차로군별 이동류
- 시간대별 회전교통량
- 대기행렬과 지체
- 실제 정책 성능

`NODE_TYPE=101`은 교차로 노드라는 뜻일 뿐 회전교차로 또는 신호교차로를 구분하지 않는다.

## 3. API로 추가 확보할 수 있는 범위

### ITS 교통소통 API

대상 링크가 서비스에 포함되면 현재 속도·통행시간·생성시각을 받을 수 있다. 이는 live overlay와 외부 통행시간 범위검사에 유용하지만, 회전교차로 구조나 신호운영계획을 제공하지 않는다.

### UTIC 신호 개방 데이터

현재 공식 활성 범위는 인천·대구이며, 외부도시 TOD·SIGNALMAP·운영계획 parser 검증에는 사용할 수 있다. 세종 실제 신호계획으로 사용할 수 없다.

### KMA·천안·KICT·제주 자료

날씨 입력, 시간대별 수요형상, 차종·회전 parser 검증에는 사용할 수 있지만 대상 세 교차로의 실제 회전교통량과 운영방식을 확정하지 않는다.

결론적으로 기존 API와 자료를 더 결합해도 성금·청사·세종을 실제 회전교차로 모델로 바꿀 수 없다.

## 4. 현재 제출본 결정

### 채택 경로

현재 실제 회랑을 유지하고 다음 범위로 고정한다.

> 신호 주기·현시·옵셋·차로군을 모델링하지 않은 합성 큐 회랑

> 실제 성금·청사·세종교차로 운영 성능 예측이 아님

- 공식 NODE/LINK는 공간 표시와 링크 길이에 사용한다.
- KMA 관측은 날씨 시계열에 사용한다.
- 지역 참조자료는 UI·adapter 기능검증에 사용한다.
- 회전교차로 가정은 실제 장소의 확인 사실로 표시하지 않는다.
- 시뮬레이터 내부 파라미터는 독립 검토 전 `synthetic-v0`로 유지한다.

### 지금 회전교차로 자료를 별도로 찾지 않는 이유

현재 세 곳을 유지하는 한 회전교차로 자료는 모델 정렬 문제를 해결하지 못한다. 다른 회전교차로의 직경·진입교통량·용량 자료를 가져오면 또 다른 지역 전이 가정을 추가할 뿐이다.

회전교차로 자료가 필요한 경우는 PM이 다음 중 하나를 명시적으로 선택했을 때뿐이다.

1. 실제 지명을 제거하고 합성 R1–R2–R3 회전교차로 데모로 복귀
2. 세종의 실제 회전교차로 3개를 새로 선정하고 해당 지점의 진입·회전교통량, 중앙섬·접근로 기하, 양보제어, 차로 수, 저장길이를 별도로 확보

둘 다 현재 실제 절재로 회랑과는 다른 프로젝트 범위 변경이다.

## 5. 구현 반영

`GET /api/reference/sejong-nodelink-status`는 다음을 제공한다.

- 공식 원본 SHA-256과 세종 413 추출 건수
- 대상 교차로 좌표
- 방향별 공식 회랑 길이
- React에서 바로 읽는 간소화 GeoJSON
- `usableForCalibration=false`
- `runtimeActivation=spatial_display_only`
- 원래 회전교차로 모델과 현재 실제 표시 회랑의 비정렬 상태
- 현재 회랑에는 회전교차로 자료가 필요하지 않다는 결정
