## 0. 먼저 읽을 결론

이번 작업은 현재 HTML을 예쁘게 다듬는 일이 아니다. HTML에서 검증된 **상태와 클릭 흐름만 인계**하고,
실제 A/B Street 도로 화면 위에 TATS의 게임 UI를 새로 설계한다.

담당자는 다음 결과를 끝까지 책임진다.

1. Manyfast V8을 복제해 `V9 UX·Unity 구현본`을 만든다.
2. 사용자가 `지도 관찰 → 진단 → 직접 신호 편집 → 영향 확인 → 적용 → 성장 → AI 비교`를
   한 흐름으로 이해할 수 있게 화면과 상태를 설계한다.
3. 승인된 V9을 Unity `UI Toolkit`으로 구현한다.
4. 정상 상태뿐 아니라 로딩, 데이터 없음, 연결 중단, 재개 실패와 위험 적용 상태까지 연결한다.
5. 1440×900과 1280×720에서 Play Mode 검증 결과를 인계한다.

로그인, 회원가입, 프로필, 계정 복구 화면은 만들지 않는다. 진행 상태는 로컬 `GameSave`에 저장한다.
서버 연결 상태와 AI 기록 조회는 게임 기능으로 유지하지만 사용자 계정 모델과 연결하지 않는다.

## 1. 사용자가 느껴야 할 게임

플레이어는 정책 카드 세 개를 누르는 운영자가 아니다. 실제 도로를 보며 교차로의 신호 단계 순서,
지속시간과 차량·보행자 우선순위를 직접 설계하는 사람이다.

화면은 다음 판타지를 증명해야 한다.

| 사용자 기대 | 화면에서 확인할 증거 |
|---|---|
| “내가 해도 지금보다는 잘하겠다” | 내가 바꾼 신호 단계와 대기열·보행자 결과가 같은 교차로에서 이어져 보임 |
| 내 설계로 지역을 살린다 | 정체·이탈 감소와 목적지 도착 유동량 증가가 지도와 수치에 함께 반영됨 |
| 성장으로 더 어려운 문제를 만든다 | 도로 개방·건물 업그레이드 뒤 새 차량과 보행자가 인접 도로에 나타남 |
| 알고리즘을 배우고 실험한다 | 원리와 trade-off를 읽고 AI 초안을 만든 뒤 직접 고칠 수 있음 |
| 실제 AI를 이긴다 | 같은 시작 조건의 Luna·Terra·Sol 기록과 유동량·안전·성장 과정이 비교됨 |

숫자만 바뀌고 지도에서 차량, 보행자, 혼잡, 건물 외형이 변하지 않으면 완료가 아니다.

- 교차로·건물·도로 선택에 따라 우측 패널이 교체되는 동작

- 정지·1·3·5배속과 선택·카메라 상태 보존
- 선택한 알고리즘으로 AI 신호 초안을 만드는 흐름

### 2.3 HTML에서 복제하지 않을 것

- CSS 도형으로 만든 가짜 교차로, 건물과 도로
- 일반 관리자 대시보드처럼 보이는 흰색 KPI 카드 나열
- 모든 정보에 같은 테두리와 같은 강조를 적용하는 구조
- `OVR`, `SIG`, `ALG` 같은 영문 약자 중심 아이콘
- 설정창처럼 보이는 평면적인 스킬 트리
- 지도 변화 없이 숫자와 토스트만 갱신되는 피드백
- 화면 하단에서 신호 길이 블록을 끼워 맞추는 타임라인

## 4. 기본 화면 구조

기준 해상도는 1440×900, 최소 지원 해상도는 1280×720이다. 지도는 항상 가장 넓은 영역을 차지한다.

```text
┌──────────────────────────────────────────────────────────────────────────┐
│ Day/시각 · 포인트 · 정지/1/3/5배속 · AI 상대 · 서버 상태              │
├──────────────────────────────────────────────────────┬───────────────────┤
│                                                      │ Context Inspector │
│ A/B Street 실제 도로 기반 도시 지도                 │ 선택 대상과 원인  │
│ 차량·보행자·신호·건물 외형                          │ 다음 행동 1개     │
│ 활성 진단 오버레이가 지도에 직접 표시됨             │ 범례·단위·tick    │
│                                                      │                   │
├──────────────────────────────────────────────────────┴───────────────────┤
│ 선택 기능의 목적·입력·예상 결과를 설명하는 한 줄                        │
│ [선택] [진단] [신호 편집] [스킬북] [도로 개방] [건물] [AI 비교]         │
└──────────────────────────────────────────────────────────────────────────┘
```

### 4.1 영역별 책임

| 영역 | 항상 보여줄 것 | 바뀌는 것 | 금지 |
|---|---|---|---|
| 상단 HUD | 도시 시각, 포인트, 배속, AI 상대, 연결 상태 | 정산까지 남은 시간, AI 격차, 적용 상태 | 큰 KPI 카드, 계정 메뉴 |
| 지도 | 실제 도로, 차량·보행자, 신호, 건물 | 선택 강조, 오버레이, 개방·성장 결과 | 가짜 CSS 지도, 패널에 가려진 핵심 교차로 |
| Context Inspector | 선택 대상 제목, 현재 상태, 주 행동 1개 | 교차로·건물·도로·진단·AI별 내용 | 서로 무관한 카드 동시 노출 |
| 하단 도크 | 7개 기능과 현재 활성 기능 | 한 줄 설명, 보조 레이어 행 | 신호 블록 타임라인 |
| 전체 오버레이 | 현재 도시 맥락을 잃지 않는 배경 | 스킬북, 영향 미리보기, 연결 복구 | 여러 모달 중첩 |
| 알림 영역 | 적용·구매 결과 | 성공, 경고, 실패와 해결 행동 | 결과 근거 없는 장식용 토스트 |

우측 패널은 기준 해상도에서 360~400px을 사용하되, 1280×720에서는 지도 판독을 해치지 않는 범위에서
폭과 내부 간격을 줄인다. 클릭·포커스 영역은 최소 44×44px을 지킨다.

### 4.2 시간·포인트·AI 표시 규칙

- 목표 총 플레이시간은 약 90분이다.
- 1배속에서 실제 1분은 도시 시간 1시간이다. 3배속과 5배속은 도시 시간과 교통 흐름에 함께 적용한다.
- 첫 온보딩은 Day 1 03:00 정지 상태로 시작한다. 안내 이후 기본값은 1배속이며 패널을 열어도 자동 정지하지 않는다.
- 연결 중단은 사용자가 고른 배속과 관계없이 즉시 강제 정지한다.
- 매 도시 시간 정산 포인트는 `기본 10 + 비교 기준 대비 완료 유동량 증가 보너스`다.
- 유동량이 감소하면 증가 보너스만 `+0`이 되고 이미 가진 포인트는 깎지 않는다.
- Day 1은 기본 신호 계획의 같은 시간대를 비교 기준으로 쓰고, Day 2부터는 전날 같은 시간대를 함께 보여준다.
- 플레이 시작 전에 3개 시작점 중 하나와 Luna·Terra·Sol 중 상대 하나를 선택한다. AI 기록은
  `3개 시작점 × 3개 모델`의 9개 조합을 일차 단위로 조회한다.
- 진행 중 HUD에는 선택한 AI 상대와 현재 완료 유동량 격차만 간결하게 보여주고 자세한 과정은 AI 비교에서 연다.

### 5.1 7종 진단 레이어

| 레이어 | 지도 표현 | 우측 정보 | 바로 이어지는 행동 |
|---|---|---|---|
| 교통량 | 도로 두께·흐름 입자, 차량/보행자 구분 | 완료 유동량, 유입량, 포화도 | 병목 교차로 선택 |
| 대기열 | 접근 방향별 막대·화살표 | 차량 수·길이, 유입 포기 임계 | 관련 신호 편집 |
| 보행자 이탈 | 횡단 대기 영역 패턴·이탈 아이콘 | 평균·최대 대기, 이탈 수 | 영향 단계 선택 |
| 신호 현시 | 현재 녹색 이동·다음 단계 점선 | 현재·다음 단계, 남은 시간, 주기 | 신호 편집 |
| 안전 위험 | 충돌 동선 교차·위험 패턴 | 중첩 흐름, 아차사고, 사고·차단 가능성 | 위험 단계 수정 |
| 건물 유입 | 건물→도로 화살표·생산 열지도 | 차량·보행자 생산량, 시간대 배율 | 건물 선택·업그레이드 |
| 도로 개방 | 개방·잠금·구매 가능 경계 | 조건, 비용, 신규 건물·수요 | 개방권 구매 |

한 번에 하나의 레이어만 활성화한다. 레이어 전환은 선택 대상, 카메라, 정지·배속을 바꾸지 않는다.
색만으로 의미를 전달하지 않고 패턴, 방향, 아이콘과 수치 배지를 함께 쓴다.

## 6. 핵심 사용자 흐름

### 6.1 첫 3분

1. 게임은 Day 1 03:00의 가장 한적한 시간대에서 정지 상태로 시작한다.
2. `신호 현시` 오버레이를 켜 현재 단계와 다음 단계를 읽는다.
3. 시작 교차로를 선택해 한 단계의 지속시간 또는 우선순위를 바꾼다.
4. 영향 미리보기에서 대기열·보행자 대기·안전 변화를 확인한다.
5. 서버 적용 예약과 안전 전환 뒤 기본 지도로 돌아가 결과를 관찰한다.
6. 세 번째 도시 시간 정산에서 현재값, 비교 기준, 기본 10포인트와 증가 보너스를 읽는다.
7. 첫 연결 도로를 구매한다.

안내는 정답 신호 계획을 주지 않는다. 각 단계는 한 번에 행동 하나만 요구하고 언제든 건너뛰거나 다시 열 수 있다.

### 6.2 직접 신호 편집

`교차로 선택 → 현재 계획 확인 → 로컬 초안 편집 → 영향 미리보기 → 서버 확인 → 적용 예약 → 안전 전환 → 활성`

- 단계 순서는 번호와 방향 미니맵이 있는 목록으로 편집한다.
- 지속시간은 초 단위 숫자 입력과 ± 버튼을 제공한다.
- 차량 이동과 보행 횡단 허용, 우선순위를 직접 선택한다.
- 황색, 전적색, 보행자 정리시간과 전체 주기는 자동 계산값으로 표시한다.
- 현재 서버 계획과 로컬 초안을 동시에 구분한다.
- 위험 계획은 차단하지 않는다. 충돌 방향, 예상 감점, 사고·도로 차단 가능성을 보여주고
  `위험 감수 적용`을 별도 행동으로 제공한다.

### 6.3 스킬북과 AI 초안

`스킬북 → 알고리즘 원리·trade-off 확인 → 해금 → 적용 대상 선택 → AI 초안 생성 → 직접 수정 또는 미리보기`

- 스킬북은 중앙의 펼친 책과 연결된 스킬 트리로 표현한다.
- 잠김, 해금 가능, 해금됨을 색상 외 실루엣·선행선·상태 문구로 구분한다.
- AI는 선택한 알고리즘 정의 밖의 전략을 섞지 않는다.
- AI 초안은 직접 편집 초안과 같은 `SignalPlan`과 같은 적용 절차를 사용한다.

### 6.4 건물 성장

`건물 선택 → 차량·보행자 생산량 확인 → 다음 외형·수요 비교 → 포인트 구매 → 지도 외형·인접 수요 갱신`

- Level 1→2, Level 2→3을 건물별로 구매한다.
- Level 2는 기본 수요의 `1.2×`, Level 3은 `1.5×`다.
- Level은 색만이 아니라 높이, 폭, 지붕, 간판 또는 대표 시설의 실루엣으로 구분한다.
- 포인트 부족, 최대 Level, 미개방 건물, 연결 중단에는 버튼을 비활성화하고 이유를 바로 표시한다.

### 6.5 도로 개방과 AI 비교

- 도로는 현재 열린 영역과 연결된 후보만 구매할 수 있다.
- 구매 전 비용, 추가 노드·건물과 차량·보행자 수요 변화를 보여준다.
- 플레이어와 AI는 같은 시작 노드와 포인트 규칙에서 출발하고 각자 포인트가 모일 때 도로를 연다.
- 비교의 주 지표는 목적지 도착을 완료한 차량+보행자 유동량이다.
- 안전, 사고, 포인트, 개방 도로와 건물 Level은 결과를 설명하는 보조 지표다.

### 6.6 연결 중단과 재개

1. 연결이 끊기면 도시 시간과 입력을 즉시 정지한다.
2. 마지막으로 확인한 서버 tick, 정지한 도시 시각과 자동 재시도 상태를 보여준다.
3. 개발 fixture나 사전 기록으로 플레이를 계속하지 않는다.
4. 재연결 뒤 서버 tick과 로컬 체크포인트가 일치하면 `재개 준비`로 전환한다.
5. 검증에 실패하면 임의로 병합하지 않고 이유, 재시도와 게임 종료를 제공한다.

### 8.2 구현 경계

- 격리된 `MapWorldController`의 지도·카메라·월드 오브젝트 책임만 참고하고 TATS namespace의 어댑터로 다시 구현한다.
- 새 TATS API client와 저장 서비스는 UI에서 직접 호출하지 않고 상태 조정자 또는 presenter를 통한다.
- UXML은 구조, USS는 스타일, C# presenter는 상태 바인딩과 이벤트 연결을 담당한다.
- UI가 교통량, 포인트, 안전 점수와 업그레이드 비용을 계산하지 않는다.
- UI는 서버·콘텐츠 응답의 값, 단위, 버전과 tick을 그대로 표시한다.
- 화면 위 투명 요소가 지도 클릭·팬·줌을 가로채지 않게 picking 영역을 제한한다.
- `RainFlowGameController.OnGUI`는 `archive/legacy-rainflow-v1/`에만 보존한다. 현재 Unity 프로젝트에 복원하거나
  UI Toolkit 화면과 동시에 노출하는 상태는 허용하지 않는다.

### 8.3 화면 상태

```text
PrimaryMode     = Select | Diagnose | SignalEdit | Skillbook | RoadUnlock | Building | AICompare
SelectionKind   = None | Intersection | Building | Road | DiagnosticSegment
OverlayType     = None | Traffic | Queue | PedestrianAbandonment | SignalPhase
                  | SafetyRisk | BuildingInflow | RoadUnlock
SimulationSpeed = Paused | X1 | X3 | X5
ConnectionState = Connected | Applying | Reconnecting | ResumeReady | ResumeFailed
SignalDraftStatus = Clean | Dirty | Validating | Scheduled | SafeTransition | Active | Rejected
AsyncState      = Loading | Ready | Empty | Error | Stale
```

상태 불변식은 다음과 같다.

- 한 번에 `PrimaryMode` 하나와 `OverlayType` 하나만 활성화한다.
- 진단 레이어를 닫아도 `SelectionKind`, 카메라와 `SimulationSpeed`는 유지한다.
- 스킬북과 영향 미리보기는 지도 맥락을 보존하지만 지도 입력을 막는다.
- 연결 중단은 현재 모드와 초안을 보존하면서 모든 변경 입력을 막는다.
- `SignalDraftStatus=Dirty`일 때 다른 교차로로 이동하면 저장·폐기 선택을 먼저 해결한다.
- 같은 명령의 중복 제출을 막고 응답 전에는 적용·구매 버튼을 재활성화하지 않는다.

## 10. 현재 구현 준비 상태

현재 코드는 과거 RainFlow 세로 조각이다. 최신 화면이 아직 구현됐다고 가정하면 안 된다.

| 영역 | 현재 저장소 | 목표와 차이 | 담당자 행동 |
|---|---|---|---|
| 화면 시스템 | 활성 구현 없음; 과거 OnGUI는 `archive/`에 격리 | UI Toolkit 셸 필요 | mock ViewModel과 셸부터 구현 |
| 조작 계약 | `contracts/game-v2` 논리 필드만 정의 | JSON Schema/OpenAPI 미동결 | mock ViewModel로 UI 제작, 계약 확정 후 연결 |
| 지도 | 과거 `MapWorldController`는 `archive/` 참고용 | 교차로·방향·보행 횡단 선택 필요 | TATS 지도 어댑터와 선택 ID 계약 구현 |
| 저장 | 활성 구현 없음; 과거 GameSave는 `archive/` 참고용 | 신호 계획·tick·도시 시각·스킬 상태 필요 | TATS GameSave 스키마 계약 작성 |
| API | 활성 구현 없음; RainFlow API는 `archive/`에 격리 | game-v2와 연결 중단 즉시 정지 필요 | 개발 mock과 제품 runtime을 분리 구현 |
| 오버레이 | 없음 | 7종 Snapshot·범례 없음 | 단일 레이어 상태와 renderer 어댑터 제작 |
| 스킬북 | 없음 | AlgorithmSkill·해금·AI 초안 없음 | 콘텐츠 mock으로 컴포넌트 선행 제작 |
| 건물 | 지역 단위 Level 외형 변경 일부 | 건물별 생산량·인접 도로·구매 상태 부족 | BuildingInspector 계약 연결 |
| AI 비교 | 과거 mission opponent 결과 | 24시간 Luna·Terra·Sol 기록 비교 없음 | 조회 상태와 비교 UI부터 분리 구현 |

담당자는 누락된 게임 규칙을 임의로 정하지 않는다. 화면에 필요한 필드, 단위, 로딩 상태와 사용자 행동을
정의한 뒤 기획·서버 담당자에게 계약으로 요청한다.

## 11. 구현 순서와 승인 게이트

| 순서 | 납품 | 승인 조건 |
|---|---|---|
| 1 | Manyfast V9 상태 인벤토리 | M01~M18의 위치와 연결 관계가 보임 |
| 2 | `n6`, `n7`, `n9` 재설계 | 지도 중심 위계와 핵심 루프가 승인됨 |
| 3 | 클릭 프로토타입 | 첫 3분, 직접 편집, 스킬북, 연결 복구가 끊기지 않음 |
| 4 | 컴포넌트·토큰·에셋 명세 | Unity에서 추가 해석 없이 제작 가능 |
| 5 | UI Toolkit 화면 셸 | HUD·지도·Inspector·Dock이 두 해상도에서 정상 |
| 6 | 선택·진단·신호 편집 연결 | 상태 보존과 단일 오버레이 규칙 통과 |
| 7 | 스킬북·성장·AI 비교 연결 | 정상·빈 데이터·오류 상태 통과 |
| 8 | 연결 복구·접근성·입력 검증 | 즉시 정지, tick 표시, 키보드·대비 기준 통과 |
| 9 | 최종 인계 | Manyfast 링크, 실행법, 검증 기록, 미연결 계약 제공 |

Manyfast 2단계 승인 전에는 Unity에서 최종 스타일을 대량 제작하지 않는다. UI 상태 모델, presenter와
데이터 어댑터는 병렬로 준비할 수 있다.

## 12. 수락 테스트

### 12.1 화면·입력

- [ ] 1440×900과 1280×720에서 지도, Inspector와 Dock이 잘리지 않는다.
- [ ] 현재 모드, 선택 대상, 게임 속도와 연결 상태를 즉시 구분할 수 있다.
- [ ] 지도에 필요한 클릭·팬·줌이 UI 투명 영역에 막히지 않는다.
- [ ] 모든 주요 기능은 아이콘, 이름과 한 줄 설명을 함께 제공한다.
- [ ] `Esc`가 현재 오버레이·모달을 한 단계만 닫고 이전 선택을 보존한다.
- [ ] 키보드 포커스 순서가 화면 읽기 순서와 일치한다.
- [ ] 클릭 영역은 44×44px 이상, 본문 대비는 4.5:1 이상이다.

### 12.2 진단·신호

- [ ] 7개 레이어 중 하나만 활성화된다.
- [ ] 레이어, 지도 강조, 범례와 Inspector가 같은 tick의 값을 표시한다.
- [ ] 레이어를 닫아도 카메라, 선택 대상과 배속이 유지된다.
- [ ] 현재 계획과 로컬 초안을 동시에 구분한다.
- [ ] 직접 편집과 AI 초안이 같은 영향 미리보기·안전 적용 절차를 사용한다.
- [ ] 위험 적용 전 충돌 방향, 감점과 사고·차단 가능성을 읽을 수 있다.

### 12.3 스킬북·성장·AI

- [ ] 스킬북에서 잠김·해금 가능·해금됨과 선행 관계를 구분한다.
- [ ] 선택하지 않은 알고리즘이 AI 초안에 섞이지 않았음을 요약에서 확인한다.
- [ ] 건물 Level 1·2·3을 지도 원거리에서도 실루엣으로 구분한다.
- [ ] 업그레이드 뒤 포인트, 생산량, 인접 수요와 외형이 같은 결과로 갱신된다.
- [ ] 도로 구매 전 비용과 신규 차량·보행자 수요를 확인한다.
- [ ] AI 비교의 주 지표가 목적지 도착 완료 차량+보행자 유동량이다.

### 12.4 연결·데이터

- [ ] 연결 중단 즉시 도시 시간이 정지하고 마지막 확인 tick이 보인다.
- [ ] 연결 중단 상태에서 편집·구매·적용 명령을 보낼 수 없다.
- [ ] runtime에서 fixture로 계속 플레이하지 않는다.
- [ ] 재개 검증 성공과 실패 상태를 각각 재현한다.
- [ ] Loading, Empty, Error, Stale 상태가 빈 패널과 구분된다.
- [ ] Play Mode에서 legacy OnGUI와 UI Toolkit 화면이 중복 노출되지 않는다.

### 12.5 첫 3분

- [ ] Day 1 03:00 정지 상태에서 시작한다.
- [ ] 현시 판독, 한 단계 편집, 영향 확인, 안전 적용과 결과 관찰을 완료한다.
- [ ] 세 번째 도시 시간 정산에서 기본 10포인트와 증가 보너스 근거를 읽는다.
- [ ] 첫 연결 도로 구매까지 도달한다.
