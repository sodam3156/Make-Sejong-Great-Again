# 프로젝트 전체 맥락

## 1. 프로젝트가 시작된 질문

세종은 스마트시티와 미래교통 분야에서 많은 지원을 받았고, 행복도시에는 CCTV·검지기·광통신망·온라인 신호제어기·스마트교차로·C-ITS 실증 기반이 존재한다. 그런데 시민이 느끼는 출퇴근 정체와 불합리한 신호 문제는 계속된다.

이 모순에서 프로젝트가 시작됐다.

> “시설은 이렇게 많이 깔렸는데, 왜 여러 교차로를 함께 보고 실시간으로 최적화하는 운영 소프트웨어는 작동하지 않을까?”

조사 결과, 문제는 단순히 “ITS가 없다”거나 “AI 기술이 없다”가 아니었다. 시설 구축, 국가 R&D, 실제 도시 운영이 서로 다른 사업과 책임 구조로 나뉘면서 **데이터 수집부터 제어·검증까지 이어지는 운영 고리**가 완성되지 않은 것이 핵심이었다.

## 2. 현재까지 확인한 결론

### 세종에 있는 것

- 도시통합정보센터와 교통정보 수집·제공 체계
- CCTV·검지기·광통신 기반 온라인 신호제어 인프라
- 버스정보시스템
- 1생활권 스마트교차로 14개소, 스마트횡단보도 10개소 실증
- 대전–세종 C-ITS와 자율주행 대중교통 실증 경험
- 계획도시 특성상 축 단위 실험이 비교적 쉬운 도로 구조

### 세종에 부족하거나 운영이 불완전한 것

- 서로 다른 장비와 세대의 데이터를 정규화하는 통합 계층
- 여러 교차로를 동시에 분석하는 상시 운영형 최적화
- 현장 제어기까지 안전하게 이어지는 신뢰성 높은 연결
- AI 추천의 근거, 승인, 적용, 롤백을 남기는 운영 워크플로
- 적용 전후 시민 체감과 KPI를 계속 검증하는 피드백 루프

### 중요한 구분

KISTI의 딥러닝 기반 다교차로 실시간 신호제어 기술과 같은 연구 성과가 존재하더라도, 특허·알고리즘·실험실 시제품과 24시간 도시 운영 제품은 다르다. 실제 제품에는 다음이 추가로 필요하다.

- 현장 장비 어댑터와 표준 인터페이스
- 통신 장애와 장비 불량 처리
- 보행·차량 안전 제약
- 운영자 승인과 수동 전환
- 감사 로그와 사고 재현
- 실패 시 기존 TOD 신호계획으로 복귀
- 유지보수 책임과 기관 간 권한 합의

## 3. 왜 세종인가

화성은 민간·경찰·교통기관과 함께 AI 신호 최적화 적용 경험이 있어 첫 상용 실증 성공 가능성이 높다. 반면 세종은 계획도시, 스마트시티 상징성, 기존 광통신·제어 인프라, 명확한 운영 공백이 함께 있어 **기술적·정책적 시연 효과**가 크다.

이 프로젝트는 “세종에 인프라를 새로 깔자”가 아니다.

> 이미 구축된 인프라를 연결하고, 안전하게 판단하고, 사람이 승인하고, 효과를 증명하는 운영 소프트웨어를 만들자.

## 4. 세종 AX 해커톤과의 연결

- 대주제: AI 콘텐츠 제작
- 소주제: SW 서비스 개발
- 제출 목표: 데모와 발표자료
- 프로젝트 강점: 세종의 구체적 문제, AI가 필요한 이유, 시각적으로 강한 관제 데모, 공공 안전에 맞는 인간 승인 구조

이 프로젝트에서 AI가 만드는 “콘텐츠”는 단순 문장이 아니다.

- 교차로별 상태 요약
- 정체 원인 가설
- 신호 운영 후보안
- 후보안별 예상 효과와 부작용
- 운영자에게 제시되는 설명과 결정 근거
- 적용 후 자동 생성되는 성과 리포트

## 5. 기존 팀 아이디어와의 연결

기존 집현전형 멀티에이전트의 장점은 유지하되, 교통 안전 도메인에 맞게 역할을 바꾼다.

| 기존 아이디어 자산 | 교통 프로젝트 적용 |
|---|---|
| 여러 전문가 AI의 토론 | 흐름·보행·긴급·장비 관점의 대안 평가 |
| 사용자 개입 | 교통 운영자의 승인·거부·수정 |
| 가중치 조절 | 지체 최소화, 보행 안전, 긴급차량 우선순위 |
| 토론 시각화 | 후보안이 채택·탈락하는 과정을 관제 UI로 표현 |
| 종합 결과 | 안전 가드를 통과한 최종 신호 운영안 |
| 분산 승인 하네스 | 다중 검토와 인간 승인 없이는 적용 불가 |

## 6. 이 프로젝트가 하지 않는 주장

- 세종시 전체 346개 또는 366개 교차로가 모두 같은 상태라고 단정하지 않는다.
- KISTI 특정 특허가 세종에 도입됐다고 주장하지 않는다.
- 해커톤 데모가 실제 교통신호를 제어한다고 주장하지 않는다.
- LLM만으로 신호 안전을 보장한다고 주장하지 않는다.
- 시뮬레이션 개선률을 실제 시민 효과로 포장하지 않는다.

## 7. 프로젝트의 최종 방향

### 단기

5~10개 교차로 디지털 트윈에서 운영자 승인형 AI 최적화 흐름을 완성한다.

### 중기

읽기 전용 실제 데이터 또는 공개 교통 데이터와 연결하고 섀도 모드에서 추천 품질을 검증한다.

### 장기

표준 제어기 연동, 기관 공동 검증, 제한 구간 승인형 적용, 안전 인증을 거쳐 폐루프 운영으로 확장한다.
